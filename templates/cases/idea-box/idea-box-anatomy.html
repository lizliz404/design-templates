ACT 1 · 先看见，不急着解释

一句 prompt 到一个页面，中间没有魔法

对小林来说，AI 似乎“啪”一下就把产品变出来了。对电脑来说，它必须经过一连串可以定位、可以失败的状态。

02生成 Source Code先产生代码内容
03写成 Files保存进某个目录
04Build / 准备得到可交付产物
05产生 Process程序开始一次运行
06浏览器画出来小林看到结果
老师可以这样说

“今天所有名词，都挂在这条线上。我们不按词典顺序背。小林每往回追问一次‘这个页面怎么来的’，就会自然撞见一组概念。”

第一条判断

页面看起来像模像样，是链路最后一格的证据；不能倒推前面每一格都正确。

ACT 2 · 第一次往下拆

小林看到的是 Application；托住它的是整台电脑

小林眼前同时开着两个应用：AI 编程工具和浏览器。Idea Box 显示在浏览器里面，但真正执行工作的不只有浏览器。

人 · 小林提出目的：“帮我做 Idea Box。”
ApplicationAI 编程工具帮助写项目；Browser 显示并操作 Idea Box。应用是面向人完成任务的软件。
Operating SystemmacOS / Windows / Linux 管文件、内存、进程、设备和权限，让上面的应用不必自己直接控制硬件。
CPU + RAMCPU 正在执行指令；RAM 暂时放着正在运行所需的代码和数据。
Disk / StorageSSD 把 idea-box 项目保存下来；关机后通常还在。

CPU · CENTRAL PROCESSING UNIT中央处理器

执行机器指令的硬件。它不会直接理解“做个网页”这句自然语言；它执行的是 AI 工具、浏览器、操作系统等软件最终变成的底层指令。

小林点击“保存灵感”时，CPU 在执行浏览器和页面相关的指令。

MEMORY / RAM内存

正在运行时使用的高速临时工作区。断电后通常不保留。RAM 越紧张，同时开的编辑器、浏览器标签和构建任务越容易变慢。

此刻输入框里的文字、页面当前状态、运行中的代码，都可能正在 RAM 里。

DISK / STORAGE磁盘 / 存储

长期保存文件和应用的硬件介质，例如 SSD。保存到 Storage 与“当前在 RAM 里看见”不是一回事。

AI 真正写入的 index.html 保存在 SSD 上，关掉工具再打开仍可读取。

OPERATING SYSTEM · OS操作系统

协调硬件并向应用提供文件、窗口、进程、内存、权限等基础能力的系统软件。

小林的 macOS 决定浏览器进程能拿多少资源、AI 工具能不能写那个目录。

APPLICATION应用程序

为用户完成一类任务的完整软件。浏览器、编辑器、AI 编程工具都是 Application。Idea Box 如果被做成独立产品，也可以成为 Application；此刻它首先是浏览器里运行的一个网页。

“浏览器”和“浏览器里展示的 Idea Box”不要一口气混成一个东西：前者是承载它的应用，后者是这次项目产生的页面体验。
老师可以这样说

“把电脑想成一家正在营业的工作室：Storage 是仓库，RAM 是今天摊开的工作台，CPU 是实际动手的工人，OS 是调度和门禁，Application 是你来这里要使用的具体服务。”

接着往回追：AI 说“我做完了”，它在磁盘上究竟留下了什么？
ACT 2 · 找到项目的身体

Idea Box 不是“一个代码”，而是一棵文件树

小林在屏幕上看到一个整体；OS 在磁盘上看到的是一组有名字、有位置的文件和目录。AI 修改的真正对象通常就在这里。

idea-box/
├── index.html       页面结构
├── styles.css      视觉样式
├── app.js          交互逻辑
├── assets/
│   └── star.svg       星星图形
├── package.json       项目说明
└── dist/
    ├── index.html   构建产物
    └── app.js
Directory · 目录

idea-box/、assets/、dist/ 是用来组织文件与子目录的容器；也常被口语叫 folder。

File · 文件

app.js 是 OS 可按名字读写的一段持久化数据，不等于“正在运行的 app”。

Filename · 文件名

styles.css 是完整文件名；名字让人和程序能够指向它。

File Extension · 文件扩展名

.css、.js 是文件名的一部分，通常提示格式或用途；改后缀不会自动改变里面的内容。

回到小林

当小林说“把星星改成红色”，AI 可能改的是 styles.css，也可能改 star.svg，还可能只改了构建后的 dist/。视觉结果相似，修改位置却决定以后能否维护。

老师可以这样说

“页面是你看到的成品，文件树是它在磁盘上的身体。以后 AI 说改好了，你先问：改了哪个文件？这是 Source 还是 Build 之后的产物？”

ACT 2 · 给文件一个准确地址

知道“有 app.js”还不够：它到底是哪一个？

小林的电脑里可能有十个项目都叫 app.js。Path 解决的不是“文件叫什么”，而是“从哪里走到这个文件”。

Absolute Path
绝对路径
/Users/xiaolin/Projects/idea-box/app.js从文件系统的固定起点写起，地址比较完整。Windows 可能写作 C:\Users\xiaolin\Projects\idea-box\app.js。
Working Directory
工作目录 / CWD
程序或工具此刻把哪个目录当作相对路径的起点。
Relative Path
相对路径
./app.js从当前 Working Directory 出发；写法短，但意义会随“站在哪里”变化。
实际解析成
/Users/xiaolin/Projects/idea-box/app.js✓ 正在指向 Idea Box 的 app.js
小林会遇到的坑

AI 回答“已修改 ./app.js”，但如果工具的 Working Directory 错了，它可能改到另一个项目，或者报“找不到文件”。同一个 Relative Path，在不同起点会指向不同地方。

老师可以这样说

“Absolute Path 像写完整门牌；Relative Path 像说‘从我现在站的位置往前走两步’；Working Directory 就是你现在站的位置。AI 站错房间，路线写得再对也会走错。”

那我怎样告诉电脑这些路径？

以后你会经常在 Terminal 里通过 Shell 输入命令、切换 Working Directory。本节只先理解“路径依赖起点”；Terminal / Shell 的交互方式留到第 10 节系统讲。

ACT 2 · 有地址，不等于有钥匙

Path 回答“在哪”；Permission 回答“准不准”

AI 即使找对了 Idea Box 的目录，也未必被允许查看、修改或启动里面的对象。权限是 OS 对主体能做什么的规则。

RRead Permission · 读权限

允许读取内容。没有它，AI 可能知道文件存在，却打不开 app.js。

WWrite Permission · 写权限

允许修改文件，或在相应目录中新建、删除条目。能读不代表能保存。

XExecute Permission · 执行权限

允许把适用对象当作可执行程序启动。它不等于“能阅读代码”，具体规则也因 OS 和启动方式而异。

回到小林

AI 能解释 app.js，说明它至少获得了某种读取能力；它真正保存修改还需要写入能力；点击“Run”时，启动脚本或程序又涉及相应执行规则。文件存在、路径正确、权限允许是三道不同的门。

老师可以这样说

“告诉外卖员门牌号是 Path；小区保安让不让进是 Permission。地址正确不会自动发一张通行证。这也是为什么 Vibe coding 工具会问你‘是否允许访问这个文件夹’。”

ACT 2 · 从文字材料到可运行产物

Source Code 描述“怎么做”；运行才真的“在做”

磁盘上的 app.js 只是一段文本。它描述点击以后应该发生什么，但静静躺着时不会自己监听按钮，也不会自己画出卡片。

SOURCE CODE人能维护的源代码

index.html、styles.css、app.js

→
COMPILE / INTERPRET + BUILD翻译、处理、组合

检查、转换、打包、复制资源；项目不一定每一步都有。

→
PROGRAM ARTIFACT可交付的程序材料

例如 dist/ 里的页面文件。

Runtime · 运行时环境浏览器提供执行网页代码时需要的环境；启动后，程序产物才在这个环境里产生真实行为。

SOURCE CODE源代码

开发者和 AI 编写、阅读、维护的原始程序表达。它是程序的来源材料，不等于某一次运行。

Idea Box 的 app.js 写着“点击保存后新增卡片”的逻辑。

PROGRAM程序

一组可以让计算机执行特定任务的指令及相关材料。一个 Program 可以被关闭、复制，也可以启动多次。

构建后的 Idea Box 页面文件可以作为可运行的程序材料被浏览器加载。

COMPILE编译

把一种程序表示翻译成另一种更接近目标执行环境的表示，常在运行前完成。不同语言和工具链做法不同。

如果小林用 TypeScript，构建流程可能先把它编译成浏览器能处理的 JavaScript。

INTERPRET解释执行

由解释器在运行时读取程序表示并执行。现实实现常混合编译与解释，不必把语言粗暴分成永远只有一种方式。

“浏览器直接执行 JavaScript”是入门近似说法；浏览器内部可能还有即时编译等优化。

BUILD构建

把源代码与资源加工成目标产物的一套流程，可能包含编译、检查、合并、压缩和复制。

Idea Box 的 Build 把可维护的源文件整理到 dist/，供预览或发布。

RUNTIME运行时 / 运行时环境

程序真正执行时所依赖的一组环境和能力。它既可以指运行阶段，也常指提供执行能力的软件环境。

这个网页的关键 Runtime 是 Browser；其他项目也可能依赖 Node.js、Python 等 Runtime。
老师可以这样说

“菜谱是 Source Code，备好的半成品和出餐流程像 Build 产物，厨房设备和当班条件像 Runtime，真正开火才叫运行。菜谱写完，不等于菜已经端到桌上。”

别混为一谈

Compile 是一种翻译动作；Interpret 是一种执行方式；Build 是得到目标产物的整套加工流程；Runtime 是程序执行所处的环境。四个词有关系，但不是同义词。

ACT 2 · 程序开始一次真实运行

Program 是材料；Process 是它“活着的一次”

小林点击 Run / Preview 后，OS 会管理一个或多个运行实例。磁盘上的同一套程序可以启动两次；每一次运行都有自己的身份、内存和资源状态。

PROCESS AAI 编程工具
PROCESS B预览 / 构建工具
PROCESS CBrowser
CPU 在许多可运行任务之间快速安排执行；RAM 承载这些进程当前所需的数据；OS 负责创建、隔离、调度和结束它们。

PROCESS进程

程序的一次运行实例，由 OS 管理，拥有自己的身份、地址空间和资源。程序文件不动，Process 可以启动、崩溃、重启、同时存在多个。

小林关掉预览再重新 Run，通常是结束一次运行，再创建新的 Process。

THREAD线程

进程内部可被调度的执行路线。同一进程可以有一条或多条 Thread，并共享该进程的许多资源。

“页面同时能响应点击和处理别的工作”不自动证明有两条 Thread；线程数量要看真实实现，不能凭界面猜。
老师可以这样说

“剧本是 Program；今晚这场演出是 Process；同一场演出里灯光、演员、音响各自推进的工作路线，可以帮助你近似理解 Thread。剧本可以只有一份，演出却能开很多场。”

回看最底层

现在硬件概念串回来了：Source Code 和构建产物长期放在 Storage；启动后，OS 创建 Process，把运行所需内容放入 RAM；CPU 按调度执行 Thread 上的指令；浏览器最终把结果显示给小林。

ACT 2 · 离开小林这台电脑

“在我电脑能跑”与“别人拿去能跑”之间，还隔着环境

如果小林把项目发给 Windows 同事，对方有了同一批文件，也未必拥有同样的 OS、Runtime、已安装工具和权限。

概念专业解释放进 Idea Box
Install
安装		把软件及所需组件准备到目标系统，并进行必要登记或配置，使它能按预期启动。安装 Browser、编辑器或所需 Runtime；不只是“下载了一个文件”。
Uninstall
卸载		移除已安装的软件及相应系统集成。是否保留用户数据或项目文件要看范围和产品设计。卸载开发工具不应被默认理解为删除 idea-box/ 源项目。
macOSUnix 风格路径常以 / 开始；应用与权限模型有自己的约定。/Users/xiaolin/Projects/idea-box
Windows路径、可执行格式、权限和安装约定不同。C:\Users\xiaolin\Projects\idea-box
Linux同属类 Unix 系统，但发行版、依赖与桌面环境仍可能不同。/home/xiaolin/projects/idea-box
老师可以这样说

“项目文件像家具设计图；Install 更像把家具和必要配件真正安置进某套房子。换了房型、门宽、电压，不能只说‘图纸一样，所以肯定能用’。”

给 Vibe coder 的问法

不要只对 AI 说“它跑不起来”。告诉它：目标 Operating System、Absolute Path、如何启动、依赖的 Runtime、出现了什么错误。环境越明确，AI 越不容易拿另一套系统的答案硬套。

ACT 3 · 从“看起来好了”走向可验证

AI 说“完成了”，小林应该把证明拆成几层

每一层只能证明自己的那一点。越往下走，越接近“用户真的得到一个能用的东西”。

AI 回复成功只证明工具给出了这个结论；不是文件、构建或运行证据。
文件确实存在检查目标 Absolute Path 下的 Source Code，而不是只看聊天里的代码块。
Build 成功证明构建流程得到目标产物；不证明页面交互符合需求。
Process 正在运行证明有一次运行实例活着；不证明它没有卡住，也不证明打开的是正确项目。
Browser 能显示证明页面被 Runtime 加载并渲染；不证明所有按钮和状态都正确。
小林走完操作输入一条灵感 → 保存成卡片 → 标星 → 重新检查。这才验证了 prompt 里的真实用户行为。
老师可以这样说

“Vibe coding 最危险的不是 AI 会犯错，而是我们把一句‘Done’当成跨越所有层的证明。以后你要问：Done 到哪一层？”

ACT 3 · 把拆开的东西重新拼起来

现在再看 Idea Box：它是一条系统，不是一张页面

同一个例子已经把本节所有概念连成三条支线：电脑提供承载，文件提供持久化材料，运行把材料变成当下行为。

小林在 Browser 里操作 Idea Box

电脑：谁在承载？

  1. Application 面向小林
  2. OS 管理资源与边界
  3. CPU 执行指令
  4. RAM 承载当前状态
  5. Storage 长期保存材料

文件：材料在哪里？

  1. Directory 组织项目
  2. File / Filename / Extension 定位对象与格式线索
  3. Absolute / Relative Path 描述位置
  4. Working Directory 决定相对起点
  5. R / W / X Permission 决定允许的动作

运行：怎样活起来？

  1. Source Code 描述行为
  2. Compile / Interpret 翻译或执行
  3. Build 生成目标产物
  4. Runtime 提供执行环境
  5. Program → Process → Thread
  6. Install / Uninstall 准备或移除环境
小林的一句 prompt 最终落到某个 Working Directory 里的 Source Files；经过需要的 Build，由 Runtime 启动成 Process；OS 调度 CPU、RAM、Storage 和权限；浏览器才把结果画成眼前的 Idea Box。

最后用一句追问判断你是否真的懂了

如果小林说：“浏览器里还是旧页面，但 AI 明明说已经改好了。”你应该能沿链路往回查：它改的是不是正确的 File？路径的起点对不对？是否有 Write Permission？改的是 Source 还是旧 Build 产物？有没有重新 Build？Browser 连接的是不是那次新的 Process？——这就是这些 jargon 对 Vibe coder 的实际价值。

我们故意没有在这里继续拆什么？

浏览器地址为什么长成那样、localhost 是什么、Client / Server 如何通信、HTTP 与 API 是什么——这些属于第 01 节 Web。JavaScript 里的变量和函数属于第 02 节。Terminal 与 Shell 怎样输入命令属于第 10 节。今天先把它们在系统中的“位置”留出来，但不抢跑。
