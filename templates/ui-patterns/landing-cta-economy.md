# Landing CTA economy & copy budget

**Aliases:** 一入口原则 · 单主 CTA · 呼吸感预算 · landing 文案密度 · hedge 清理
**Job:** 把"这页看着乱"翻译成可判定的数量：**几个竞争的下一步、几层视觉权重、几段没人读的解释**。
**Why:** "按钮太多"只是症状。真正的成本主要来自**等权重歧义**和**视觉竞争**，不是"选项个数"；按错变量去删，会删掉需要的施力点。

**Reference ships（消费项目，包内不 vendor）：**
- `<project>/web/src/landing/`：全页只有一个"进入"入口（nav 常驻 + 页脚），hero 无按钮。
- `<project>/frontend/src/landing/LandingPage.tsx`：同一入口 `/setup` 出现 4 次，但页脚把它和 4 个平级链接摆成一行。

## 1. 流程（按序，终点怎么判）

1. **数"竞争的下一步"，不数按钮实例**：列出每个可点元素的目的地（同 destination 合并）。得到的是真正预算项。
2. **按 §4 定位问题类型**：等权重双主按钮 / 4 次同权重重复 / 页尾平级 / 每屏都加按钮 / 纯文案过密。不同类型修法不同。
3. **套 §5 预算**：动作种类 ≤2（1 主动作 + 1 辅助）；首屏动作目的地 ≤2；单 viewport 可点元素 ≤6；同一主动作每 1.5–2 屏一次、权重递减。
4. **套 §6 文案预算**：H1 ≤16 字、副题 ≤40 字、每段 ≤60 字、每节 ≤120 字、首屏必须露出下一屏。
5. **清 hedge**：按 §7 五问逐句判；删不掉的先改 claim。
6. **终点判定**：§8 清单全绿；"看着清爽"不算，计数和对比度才算。

## 2. 变量不是按钮数

```
成本来源                真实机制                         删什么
─────────────────────────────────────────────────────────────────────────
等权重歧义   两个目的不同、视觉同级的按钮    降级其中一个（实心 vs 文字链）
视觉竞争     同屏多个高饱和/大字/边框块      减层级，不是减入口
线性视觉搜索 唯一的下一个动作藏在多个元素里  减同屏可点元素总数
滚动回退成本 页尾没有同一入口的第二次施力点  加回同一个 CTA（不计入"多选项"）
```

**结论：一种动作可以重复；两种动作必须分主次；三种以上是事故。**
唯一的例外是产品本身就是"选一个"（定价页、套餐、目录、筛选器）——那里的选项就是产品。

## 3. 证据边界（别拿错的定律论证对的直觉）

- **Hick–Hyman 定律不能用来论证 "less is better"。** 它测的是"已知等概率刺激 + 预置反应"的毫秒级反应时，且高 S-R 兼容性下斜率极浅。原论文明确写：*"Hick's law speaks against, not for, the popular principle that 'less is better'"*。Wanyu Liu et al., *How Relevant is Hick's Law for HCI?*, CHI 2020 — <https://doi.org/10.1145/3313831.3376878>
- **"选择过载"的平均效应接近零。** Scheibehenne, Greifeneder & Todd 的元分析（50 实验、N=5,036）结论是效应可正可负、平均≈0，调节变量才是关键。所以"选项多 → 累"不能当默认前提。
- **"决策疲劳 / 意志力有限"在多实验室复制中站不住**（ego depletion 大规模复制 d≈0.04，跨零）。不要用它写设计理由。
- **真正有实证支撑的三件事**：① 首次访客的视觉搜索成本随元素数近似线性上升（不是对数）；② 两个等权重、不同目的地的 CTA 会制造真实犹豫（MECLABS 原型里 2/3 的失败案例）；③ 注意力压在首屏，且段落可见率在第 3→4 段断崖（NN/g 段落可见率 81/71/63/**32%**）。
- **"短文案转化更好"是阅读行为事实，不是转化事实。** 平均页面 593 词只有约 20% 被读；但长页在高单价/需解释机制的场景同样赢。可辩护的规则：**每句回答一个活问题**，不是"字数越少越好"。

## 4. 六种乱法，六种修法

| 症状 | 判定 | 修法 |
|---|---|---|
| 首屏两个同级主按钮 | 两个不同目的地、视觉同权重 | 一个留实心，另一个降为文字链或锚点；不要只改文案 |
| 同一 CTA 4 次都用主按钮 | 孤立效应失效，页面没有"最响的一个" | 保留次数，改成**权重递减**：hero 实心 → 中段实心/描边 → 页尾实心或大文字链 |
| 跟随式导航 + 首屏/页尾再放同一个按钮 | 入口已经常驻可见，再放就是重复 | 删掉页面里的同一入口按钮；导航是它唯一的位置 |
| 页尾 CTA 和 4 个导航链接并列 | 语义混层（动作 vs 导航） | 页尾动作单独一行、与其他链接分离；导航链接降为小字 |
| 每屏一个按钮 | 无依据的过度克制 | 按 1.5–2 屏节奏放同一动作；不必新增目的地 |
| 首屏三行标题 + 四行副题 + 免责两行 | 竞争性视觉元素 >1 | 标题 ≤16 字、副题 ≤40 字，把解释移出首屏 |

## 5. CTA 预算表

| 项 | 预算 | 依据 |
|---|---|---|
| 不同"下一步"种类 | 1 主动作（+1 辅助路径，不同意图时） | [混] Material "one primary task per page"；MECLABS 等权重歧义 |
| 首屏动作目的地 | ≤2 | [启] |
| 单 viewport 可点元素（含导航/样本卡/外链） | ≤6 | [启]，锚点：线性视觉搜索成本 |
| 同一主动作重复 | 每 1.5–2 屏一次，**但入口常驻时归零** | [启] + Material "constant access to a primary action" |
| 页尾主 CTA | **仅当入口不常驻**时必须；跟随式导航已常驻时，页尾再放就是重复 | [启] |
| 页脚法务/导航链接 | 不计入 CTA 预算 | [启] |
| 等权重主按钮 | 0 | [证] MECLABS / NN/g clickable elements / Baymard button design |

标记：[证] 有出处 · [混] 部分有出处 · [启] 启发式（无第一手依据，按项目实测再改）

## 6. 文案预算（中文 landing）

| 项 | 预算 |
|---|---|
| H1 | ≤16 字，前 2 字承载核心信息 |
| Hero 副题 | 1–2 句，≤40 字 |
| Hero 区总字数（含 eyebrow/chip/按钮标签） | ≤80 字 |
| 每段正文 | ≤60 字（≈3 行 @16px/1.7） |
| 每 section | 标题 ≤20 字 + 正文 ≤120 字 + ≤3 bullet |
| "必须被读到"的内容 | 放在前 3 段内 |
| 滚动线索 | 下一屏内容露出 ≥8% 视口高（假地板：有用户真的不知道能滚） |
| 注释/免责 | 不限字数，但**每句必须能指认它限定的 claim**；字号 ≥ 正文 70% |

**首屏真正的约束不是字数，是竞争性视觉元素 ≤1**：一个标题 + 一个支撑块 + 一个动作。

## 7. 入口的命名：用用户的下一个动作，不用实现细节

导航里的入口是整页最贵的一个词。判据：**用户心里那个动作叫什么，就用那个词。**

| 少用 | 为什么 | 换成 |
|---|---|---|
| 获取密钥 / 生成 Token / 接入 API | 描述的是系统内部机制，不是用户想做的事 | 进入 / 开始使用 / 连接我的 Agent |
| 立即注册 / 马上体验 | 描述的是转化目标，不是用户的动作 | 进入 |

同一个入口在不同位置可以用同一个词；**位置改变不该换词**，否则它就不再像“同一个地方”。

## 8. Landing 上的 hedge：三类，只有一类该删

| 类型 | 例子 | 处理 |
|---|---|---|
| 法定/合规必须 | 价格构成、赠送期限、风险提示、禁忌、金融业绩口径 | **留**，且必须显著、紧贴 claim |
| 事实来源与口径 | "观察时间 X""4 款样本""价格为此前标价""不代表销量或全站排名" | **留**。这是数据主张的法定与信任双重身份，删了就是过度承诺 |
| 纯自我防御 | "本页不构成任何承诺""以上仅为示意，实际情况可能不同""我们无法保证…" | **删**，或移入条款页 |

**五问判据**（任一为"是"就留，全为"否"就删）
1. 它限定的那句 claim 是哪一句？指不出来 → 删。
2. 删掉后这句话会不会被合理读成承诺？会 → 留（并考虑先改 claim）。
3. 它是不是法定必须显著标明的事项？是 → 留。
4. 它是给"已决定的人"看的，还是给"还在决定要不要看的人"看的？后者 → 移出首屏。
5. 如果这个 claim 需要一整段解释才不误导，问题在 claim 还是缺解释？在 claim → 改 claim。

**给 AI 的 brief 里直接写这句：**
> 只保留"不写就会被合理误读为承诺"的话，以及法律明文要求显著标明的话。其余移到细则页；如果移走之后 claim 站不住，改 claim，不要加段落。

## 9. 验收清单

- [ ] 全页不同目的地计数已写下来（不是"感觉少了"）。
- [ ] 首屏动作目的地 ≤2，且权重悬殊（实心 vs 文字链）。
- [ ] 同一主动作出现的位置与权重已写下来；入口常驻时，页面内不再出现同一入口的按钮。
- [ ] 入口用词是用户的下一个动作，不是“密钥/Token/API”这类实现细节。
- [ ] 单 viewport 可点元素 ≤6（导航、样本卡、外链都算）。
- [ ] H1/副题/段落字数在预算内；首屏露出下一屏。
- [ ] 每条注释能指认它限定的 claim；无"预防杠精"型免责。
- [ ] 窄屏（390×844）复看一遍：CTA 不折行、不与文案抢层级。
- [ ] 键盘 Tab 顺序从 skip-link → nav → 主 CTA；页尾动作可聚焦。

## 10. 边界（不要机械套用）

- 定价页、套餐页、目录页、筛选器：**选项就是产品**，允许 3+ 个 CTA，但必须同族 + 明确推荐项。
- 两类真实不同的意图（自助注册 vs 预约销售）：允许 2 个目的地，但权重必须悬殊。
- 回访用户占比高的产品：可增加"跳到 X"型入口，这不属于 landing 首屏预算。
- 受监管品类（医疗、金融、食品）：免责段落必须加，且显著性与 claim 相当；此时"删 hedge"不适用。
- 高单价、需解释机制的 offer：页可以长，但段落预算不变，前 3 段必须完成核心论证。
- 删按钮不是目的：如果删完页尾没有第二次施力点，转化会掉——先数目的地，再删。
