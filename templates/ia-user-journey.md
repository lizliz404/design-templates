# IA · 用户旅程（pack 合同）

类型：Product IA contract（非视觉系统、非 UI 实现规程）

| | |
|---|---|
| **What** | 先写可替换的信息架构 1.0（对象 + 分组 + 命名），再投影成角色路径、页面职责、导航、UI。产出是项目里的 `docs/IA.md`，不是侧栏草稿。 |
| **Why** | 导航是 UI 镀铬，不是骨架。从「这一页看起来乱」补丁页面，IA 会漂。认知负担来自**同一对象多个门**和**用库表当导航**，不是来自少几个按钮。 |
| **Who** | 1–4 人内部工具 / OA / 控制台。写给人填，也给 agent 扫。 |
| **How to use** | ① 读本文 → ② 按 §7 骨架填当前项目的 `docs/IA.md` → ③ 冻一版 `docs/prd/vN-YYYY-MM-DD.md` → ④ 再改 `nav` / 页面。 |
| **Not this** | 不是 DESIGN.md；不是空态文案大全；不是「保持简洁」口号；不是把出海云菜单抄到别的产品。 |
| **When to open** | 新内部工具定 IA；默认首页吵；侧栏像模块清单；想加菜单/Tab；用户问「今天先干什么」。 |

Filled example（填满的一份，不是唯一形状）：

- `D:\dev\chuhai-cloud\docs\prd\v3-2026-08-13.md`（冻版）
- `D:\dev\chuhai-cloud\docs\PRD.md`（当时真源）
- `D:\dev\chuhai-cloud\docs\prd\README.md`（怎么冻 / diff / rollback）
- 导航投影：`D:\dev\chuhai-cloud\web\src\app\nav.ts`

形状可变：有的产品是侧栏主链，有的是顶栏 ≤5；有的流水线是「原料→出片→铺量→收拢」，有的是「填报→缺口→定稿」。合同是闸和顺序，不是那一组名词。

## 1. 顺序（禁止倒着做）

```text
IA 模型（对象 / 分组 / 命名）
  → 角色路径（谁 × 今天干什么，用户语言）
    → 页面职责（一页装什么、不装什么）
      → 导航投影（主链顺序 + 溢出）
        → UI / 代码
```

禁止：页面看起来乱 → 在这一页打补丁 → 导航和模型各说各话。

可替换：1.0 允许错。可编辑、可带走、下一冻版能整份替换，优先于「钉死到永远」。

NN/G 转闸（不抄长文，只留可执行条件）：

| 来源 | 闸 |
|---|---|
| IA ≠ navigation | 没写完对象清单、分组、命名之前，禁止画侧栏/顶栏。导航是投影。导航和 IA 打架时，改导航或出下一冻版，禁止只改 UI 冒充改了 IA。 |
| Progressive disclosure | 第一屏 = 高频 + 重要。次要信息按需出现（更多 / 抽屉 / 帮助）。线性活路用分步披露（带下一步 URL），不要把全系统地图放进首页。 |
| Card sort / tree test | 分组必须能写成「谁 × 任务」的用户语言。库表名不能当导航标签。内部 OA ≤4 角色可跳过正式实验，但必须写任务矩阵，且找一个**非作者**按树找一件活（非正式 tree test）。找不到 = 树错了，不是用户错了。 |

## 2. 硬闸（任意内部工具）

过不了就不要加菜单、不要加产品 Tab、不要改默认首页。

**G1. 产品一句必须是「受众 + 对象动词链 + 反例 + 禁入主链的项」。禁止功能清单当定义。**

填成：`给 {谁} 一条 {杠杆/作业} 流水线：{A} → {B} → {C} → …`。下一句写「不是 {精修/单笔/报表堆}」。再点名哪些增强项不许抢主链点击。

**G2. 导航顺序 = 对象生产/流转顺序。链头只允许一个不生产对象的调度页（工作台/今天）。主链目的地 ≤7，外加一个溢出（更多/管理）。**

调度页只回答两句：今天先干什么；机器/流程跑得怎么样。全链路地图不在调度页。

**G3. 想加菜单或水平 Tab → 先改 `docs/IA.md` 对应节，再动代码。必须当场回答：**

1. 服务主链哪一段？
2. 能否并进现有页的上下滚 / 胶囊 / 抽屉？
3. 是不是同一份数据的切片？

答不出 = 不加。禁止为显得功能多加叶子。

**G4. 同一对象一个门。同一份数据的切片 = 一页上下滚 + 锚点。旧 Tab 路由改成 hash 重定向。审核需要对照时，页面文件可留、侧栏不再指向。**

切片示例（不当门）：总览 vs 按人 vs 按部门；任务列表 vs 已完成；趋势 vs 账户。时间窗、状态、平台是过滤器，不是产品。

**G5. 胶囊只切换真两套对象或两套库存。**

允许：两套归属池、两套会话类型、两类文件、人 vs 审计日志。  
禁止升级成对等产品 Tab：同一批记录的切片、工具条动作（合并/导出）、归档、状态筛（草稿/已提交）。状态筛可以长得像胶囊，但文案和 IA 必须标成「筛，不是门」。

**G6. 默认首页必须同时有：今天的队列入口（可点进对应页）+ 零状态下的下一步 URL。禁止把全系统地图放在首页。**

空态：缺什么 + 去哪补 + 一个主 CTA。帮助页才画全图。

**G7. 情境工具挂在使用现场，不进主链。帮助是溢出里的地图，禁止做成第二套 onboarding。导览只讲解铬（侧栏/顶栏），不代替调度页派活。**

**G8. 增强项进溢出的充要条件：不生产主链对象，或与主链对象法定/结构不同（两张表、两套授权、两套作业）。对象边界写进 IA 或备忘；未写入当前冻版，禁止改导航。**

两套真对象可以拆页，但不自动获得主链点击。主链只放流水线环节。

## 3. 反模式：导航 = 数据库对象

把模块/表/审批状态做成一级导航，用户要先懂你的 schema 才能办事。

内部工具高频翻车（名词可换，结构一样）：

```text
部门 / 预算 / 报表 / 审批
组织 / 单据 / 台账 / 流程
项目 / 资源 / 权限 / 日志
```

这些是**存储和权限切分**，不是用户今天的活。用户语言长这样：

```text
把今年的数填完 → 看缺口 → 定稿或被打回后改 → 主管看卡在谁
传原料 → 出一批 → 发出去 → 回话 → 跟线索
```

检测方法：拿 G3 三问去审每一片叶子。若答案是「对应一张表 / 一个微服务 / 一个审批状态」，删掉或并进真正的对象门。

非正式 tree test 口令：「你是 {角色}，今天要 {任务}。从打开产品开始，点哪里？」作者不许提示。三次里有一次迷路，改树，不要加说明文案硬扛。

## 4. 版本：真源 + 冻版（1.0 可被整份替换）

项目内约定（结构抄出海云 `docs/prd/`，文件名可仍叫 `IA.md`）：

| 文件 | 角色 |
|---|---|
| `docs/IA.md` | **当前真源**。改导航 / 页面归属 / 水平菜单之前先改它。 |
| `docs/prd/vN-YYYY-MM-DD.md` | 拍板后的冻版全文。git 可 diff / rollback。 |
| `docs/prd/README.md` | 版本表：哪一版定了什么、怎么冻下一版、怎么回滚。 |

`docs/PRD.md` 若已存在且团队认它为真源，可让它与 `docs/IA.md` 同内容或让其中一个 redirect 到另一个。**一个**当前真源，禁止两份同时改。

怎么冻下一版：

```text
复制 docs/IA.md → docs/prd/vN-YYYY-MM-DD.md
在 docs/prd/README.md 加一行
再改真源
```

对比 / 回滚：

```bash
git diff HEAD -- docs/IA.md
git diff -- docs/prd/v2-YYYY-MM-DD.md docs/prd/v3-YYYY-MM-DD.md
# 回滚真源（会改工作区，先确认）
# Windows: copy docs\prd\vN-YYYY-MM-DD.md docs\IA.md
```

改动闸：

```text
想改导航归属 / 加菜单 / 加水平 Tab
  → 先改 docs/IA.md 对应节
  → 再动 nav / router / 页面

1.0 允许错。发现错了就出 vN+1 冻版替换，不要在页面上打补丁假装模型没变。
```

代码入口（有则写进 IA 文末）：`nav.ts` / 等价导航真源、router。视觉例外写 `DESIGN.md`，不要散落注释。

## 5. 页内怎么拆（投影规则，不是视觉）

同一份数据的三个切片 ≠ 三个产品。

| 它到底是什么 | 摆法 |
|---|---|
| 真两套对象 / 两套库存 | 胶囊（少，通常 2；文件类型等可略多，仍是一个门） |
| 同一批记录按维度切片 | 一页上下滚，或页顶总览 + 下面名单 |
| 动作（合并、导出、分配） | 工具条按钮 |
| 归档 / 作废 | 左栏或筛，不进主漏斗阶段；归档里不能新建 |
| 情境工具（话术、模板、计算器） | 用得到的那一块 UI 上，侧栏不单列 |
| 增强项 | 溢出（更多），或附属列/抽屉 |

旧链：被合并的路由改重定向，不默删文件。

## 6. 调度页与披露

工作台 / 默认首页：

1. 上：今天的队列（3 块左右，可点进对应对象门）。
2. 中：零状态下一步（3 步以内，每步一个 URL）。常驻或空态出现均可，但必须有 URL，禁止只讲道理。
3. 下：流程/机器回看（同一份数一页滚）。不要再占一个「数据」导航叶子。

第一屏只放高频/重要。次要进溢出或页内下半。线性作业用分步披露，不要「下一步」空门如果不增加决策。

帮助：图说结构，字只补动作与边界；每块可点进真页面。禁止把帮助改成第二套导览。

## 7. 空白骨架（复制到 `docs/IA.md` 再填）

外层用四反引号包住，里面的 mermaid / text 三反引号可原样粘贴进项目。

````markdown
# {产品名} · IA 与用户旅程（v1 · 当前）

> 真源。改导航 / 页面归属 / 水平菜单之前先改本文，再动代码。
> 冻版目录：[docs/prd/](prd/README.md)。1.0 允许错，下一冻版整份替换。

## 1. 产品一句

给 {谁} 一条 {作业类型} 流水线：

**{A} → {B} → {C} → {D}**

不是 {反例}。{增强项 1}、{增强项 2} = 增强项，不许抢主链点击。

## 2. 对象流

```mermaid
flowchart LR
  A[{原料/输入}] --> B[{加工}]
  B --> C[{产出回库或提交}]
  C --> D[{下游动作}]
```

调度页不生产对象，只回答「今天先干什么」和「跑得怎么样」。

## 3. 谁 × 任务（用户语言，禁止库表名）

| 角色 | 今天的活（3 步以内） | 从哪进 | 不进哪 |
|---|---|---|---|
| {角色 1} | 1. … 2. … 3. … | {调度页} | {溢出项} |
| {角色 2} | 1. … 2. … 3. … | {页} | {页} |

非正式 tree test：非作者按上表找活。迷路则改树。

## 4. 主链导航

顺序本身就是产品故事。代码真源：`{nav 文件}`。

| 序 | 导航 | 路由 | 这一页装什么 | 不装什么 |
|---|---|---|---|---|
| 1 | {调度} | / | 队列 + 零状态三步；下半回看 | 全链路地图 |
| 2 | {对象门} | / | | |
| + | 更多 | — | {增强项}、帮助 | 主链对象 |

## 5. 每页装什么

### 5.1 一页滚，不要假产品 Tab

| 页 | 不要 | 要 |
|---|---|---|
| {调度} | 数据再占一个导航叶子；三个下划线 Tab | 待办在上，数据在下 |
| {页} | {假 Tab A} \| {假 Tab B} | {上} + {下} |

### 5.2 胶囊（仅真两套对象）

现在还保留胶囊的：

- {页}：{A} \| {B} — 因为 {两套对象的理由}

不当胶囊的：{切片}、{动作}、{归档}。

| 角色 | 打开产品后第一屏 | 三步 URL |
|---|---|---|
| {角色 1} | {调度页队列} | {url} → {url} → {url} |

## 7. 第一期三块

调度页最上只放这三块（可点进队列，不是装饰 KPI）：

2. {队列 B} → {路由}
3. {队列 C} → {路由}

3. …

## 8. 明确不做

- 为显得功能多加侧栏叶子
- 把帮助做成第二套导览
- 用库表名当导航标签
- 在归档里新建主链对象
- 未写入本文就改导航 / 加水平 Tab
````

## 8. Agent 执行顺序

1. 读本文件，不要直接画导航。
2. 若项目已有 `docs/IA.md` / `docs/PRD.md`，先读真源再改；不要平行再写一份。
3. 用 §7 骨架填或改 `docs/IA.md`。缺角色就问最小问题（谁、今天三步、对象链），不要用表名填空。
4. 建或更新 `docs/prd/README.md`；首次拍板后冻 `docs/prd/v1-YYYY-MM-DD.md`。
5. 导航投影另做，且顺序必须能从 §4 表一行行对上。
6. 不在本任务里实现 UI，除非用户明确说进入页面实现。

停：骨架填完、三问能审每一片叶子、非正式 tree test 口令已写进文档。不要为「完整」去发明未确认的业务规则。
