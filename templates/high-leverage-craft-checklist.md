## 三问过滤器（做之前先过）

1. **改情绪或决策吗？** 纯装饰 ≠ 杠杆。
2. **成本在「一杯咖啡 → 一个下午」吗？** 再大就走正式 ROI，别冒充四两拨千斤。
3. **3 秒内可感知，或卡在关键路径**（首次激活、付费、出错、离开）？不在关键路径上的精致，多半是自嗨。

通不过就砍。本手册按**机制**分组；`frontend` `backend` `growth` `ops` `copy` 只作次要标签。

## 一、等待：把「未知多久」换成「我知道在发生什么」

### 1. 骨架屏代替裸 Spinner `frontend`

**是什么**：用接近真实布局的浅色占位，而不是无限转圈。  
**为何杠杆**：同样等待，焦虑差在「有没有终点形状」。转圈 = 未知；骨架 = 「内容长这样，马上到」。  
**怎么落地**：按关键页面真实栅格画 3–5 块灰条；列表行高与真数据一致。  
**反模式**：骨架和真布局对不上（跳变比 spinner 更糟）；每个按钮旁都转圈。  
**开火路径**：首屏、Dashboard、列表页加载。

### 2. Optimistic UI（可回滚的先成功） `frontend`

**是什么**：点赞、勾选、排序、发送——先更新界面，后台再同步；失败再回滚并提示。  
**为何杠杆**：把 200–400ms 网络感知压成「零延迟」，专业感来自手感不是功能清单。  
**怎么落地**：React Query / SWR `onMutate` + 快照回滚；不可逆操作（支付、删库）不要乐观。  
**反模式**：对钱、权限、合规写路径做乐观；失败无回滚、无错误文案。  
**开火路径**：高频低风险交互。

### 3. 诚实的「劳动幻觉」进度文案 `frontend` `copy`

**是什么**：长任务不写 `Loading…`，写阶段事实：「正在比对航司」「生成第 3/5 段」「解析 PDF 第 12 页」。  
**为何杠杆**：Labor Illusion——看见系统在干活，满意度往往高于「更快但一片空白」。Kayak、多数 AI 长任务都靠这招。  
**怎么落地**：把后端阶段或估计步骤映射成 3–7 条人话；能量化就量化，别瞎编百分比。  
**反模式**：假进度条冲到 99% 卡住；编造不存在的步骤。  
**开火路径**：搜索聚合、导出、AI 生成、大文件处理。

### 4. 能本地先出的结果，别干等接口 `frontend`

**是什么**：过滤、搜索、排序——有缓存/本地数据就先渲染，远端结果到了再修正。  
**为何杠杆**：800ms 转圈 vs 立刻可见（哪怕标「可能不完整」），体感差一个数量级。  
**怎么落地**：先 `filter(localCache)`；远端回来后 merge，并弱提示「已与服务器同步」。  
**反模式**：把过期数据当真理且不标注；权限敏感数据勿本地先行。  
**开火路径**：设置页、资源库、带筛选的表格。

## 二、可逆：用「可反悔」换用户胆量

### 5. Undo Toast 优于确认弹窗 `frontend` `copy`

**是什么**：破坏性操作先执行，底部「已完成 · 10 秒内撤销」；不要动不动 `Are you sure?`。  
**为何杠杆**：损失厌恶——阻断确认制造犹豫，撤销把成本挪到事后，转化与情绪双赢（Gmail 撤回发送是教科书）。  
**怎么落地**：软状态挂 10–30s；过期再硬提交。支付、不可逆合规动作仍用强确认。  
**反模式**：一切都 Undo（用户不知是否真生效）；Undo 窗口短到点不到。  
**开火路径**：删除、归档、取消订阅前一步、发送邮件。

### 6. 自动保存 + 极弱「已保存」 `frontend`

**是什么**：去掉显式 Save 心智负担；右上角一行小字即可（Notion 式 `All changes saved`）。  
**为何杠杆**：用户怕丢稿；你用后台 debounce 换安心，比任何「别忘了保存」文案都强。  
**怎么落地**：输入 debounce 500–1000ms 写 draft；冲突时提示「他人已更新」而非静默覆盖。  
**反模式**：无反馈的静默保存（用户不敢关页）；每键一次全量请求。  
**开火路径**：编辑器、表单草稿、配置页。

### 7. Soft-delete：`deleted_at` 比客服便宜 `backend`

**是什么**：破坏性删除默认进回收站 15–30 天，不是物理抹掉。  
**为何杠杆**：一行字段换「删错了」客诉与信任崩盘；实现成本接近零。  
**怎么落地**：查询默认 `WHERE deleted_at IS NULL`；管理端提供恢复；到期 job 再硬删。  
**反模式**：GDPR/用户要求删除时还软留 PII；没有真正的硬删路径。  
**开火路径**：项目、文件、客户记录、账单附件。

## 三、峰终：开场与离场决定记忆

### 8. 预填示例数据，别扔空白 Dashboard `growth` `frontend`

**是什么**：新账号自带 demo 项目 / 看板卡片 / 假客户，让用户「从 1 改」而不是「从 0 想」。  
**为何杠杆**：空页第一反应常是「这东西对我没用」；Aha 被前移到改第一条示例。  
**怎么落地**：注册后写入只读或可删的 seed；空状态 CTA 写「用示例试试」或「导入自己的」。  
**反模式**：示例像广告、删不掉、和真实数据模型对不上。  
**开火路径**：Onboarding 首屏、空 workspace。

### 40. 会定格的示例轮播输入框（空投占位符） `frontend` `copy`

**是什么**：placeholder 不只是提示语，而是一块轻量的 discovery / inspiration surface。关键输入框空闲时，placeholder 用打字机轮播真实示例（灰、小、安静）；用户点进去，当前条**冻结并实体化**成「建议预览」——不写进 value，只是停在原地让人看、可被拿走。交互法则一句话：**Pause on intent. Commit on action. Resume on abandonment.**——有兴趣就停下给他看，真的操作就变成他的，没兴趣了继续洗牌。状态机：`轮播 →（pointer 点击）→ 建议预览 →（打字）→ 正常输入 /（显式采纳）→ 填入 /（空置 6–8s）→ 回轮播`。机制上是条目 8 的输入框版：示例数据收进一行输入框。  
**为何杠杆**：空白输入框对零 context 用户是「不许进」；轮播示例 = 免费能力广告位，每条案例都是一次产品演示。默认的「聚焦即消失」把围观通道掐死——案例还没被读懂就没了。定格 + 可采纳让空投被捡到：用户在轮播里等出「哎就这个了」，serendipity 直接变输入。成本一个 interval + 两行 CSS。  
**怎么落地**：  
1. 示例库 5–8 条：真实、多样、一行读完、覆盖产品不同能力面；文案取自真实用户语言（搜索词/工单/客服记录），不是营销腔——这是 miniature 功能巡演。  
2. 空闲态打字机轮播，每条补完停 2.5–4s。**pointer 点击**瞬间把当前条补完整句再冻结（冻在半个词像 bug），升成正文色；**键盘 Tab 只暂停动画、保持灰的 placeholder 样式**——路过 ≠ 意图。轮播是 JS 改 placeholder，实体化换色是 `input:focus::placeholder` / overlay 一行 CSS。  
3. 建议预览 ≠ value：不参与提交校验、变化不进 aria-live；用户一打字立即让位。真正采用走**显式动作**：hover 后浮现的轻 affordance（`↵ 用这条` / `Use example →`）或 Enter、或再点一下当前建议——轻，但必须存在，否则用户以为只是装饰。采纳快捷键只在空值预览态生效，避免和 Enter 提交打架。  
4. 复活要保守（6–8s 起步）：无任何 pointer/keyboard 互动 + 仍为空 + 无 IME 组词/选区 → 才恢复。恢复带过渡：轻 fade 回 placeholder 样式 → 停 500ms → 顺序走下一条（别随机猛跳、别重打刚冻结那条）——「放下这张牌，牌堆继续洗」。blur 留空同理；有值就停，删空失焦再回来。到点抢着跑掉的「抢凳子」比不恢复更糟。  
5. 端差异：移动端没有 hover——tap = focus，实体化立即发生，采纳 affordance 不能靠 hover 浮现，改为预览态常驻小按钮或「再点一下建议即采纳」；移动端示例更短（软键盘 + 窄视口把 placeholder 可视宽度压得很小）。`prefers-reduced-motion` 不轮播，给一条静态示例。  
6. autoFocus ≠ intent：程序聚焦（首屏自动聚焦的 brief 框）保持轮播态即可，别当成点击去实体化。纯展示行（标语/示例句）没有 focus 语义，用 hover 暂停替代。  
7. 只开在「输入框同时是 discovery surface」的场景：AI prompt 框、发现式搜索、creative tools、模板生成器；转账/登录/表单/设置页这类「我知道要填什么」的 utilitarian 输入框上，动着的 placeholder 是纯噪音。与条目 34 不冲突——轮播的是「你可以问什么」，不是假装在生成。埋一个 `example_accepted` vs 手打事件，就能验证空投有没有真被捡（对齐条目 28）。  
**反模式**：聚焦即清空（案例没被读到就没了）；focus 死算 5 秒然后抢着跑掉；冻在半个词上；不经显式采纳就写进 value（回车误提交、用户以为是自己打的）；affordance 做成 banner（SUGGESTED PROMPT / CLICK HERE 立刻土掉）；轮播快到读不完；不看状态硬轮播（组词中/已有值还在动）；utilitarian 输入框全站铺。  
**开火路径**：AI 产品主输入框、富语法/发现式搜索框、creative tools 与模板生成器的第一个输入位、一句话语义搜索（示例 query 即 query 教育）。

### 9. 完成态的克制庆祝 `frontend` `copy`

**是什么**：清空列表、首次导入成功——200ms 微动效或一句人话，不要彩带轰炸。  
**为何杠杆**：峰终定律——结尾小峰值会被记成整段体验；过度庆祝像诈骗页。  
**怎么落地**：Linear / Superhuman 量级：短文案 + 可选微动效；尊重 `prefers-reduced-motion`。  
**反模式**：每次勾选待办都放烟花。  
**开火路径**：首次价值达成、导入完成、里程碑任务。

### 10. 主动设计「离开」 `growth` `copy`

**是什么**：取消订阅 / 删账号时问一句真实原因，并给一个体面出口（降级、暂停、导出数据）。  
**为何杠杆**：不只是挽留转化；记忆里留下「最后还被认真对待」，影响口碑与回流。  
**怎么落地**：单选原因 + 可选自由文本；一键导出；别做黑暗模式多步刁难。  
**反模式**：假客服聊天关卡；藏取消按钮。  
**开火路径**：Billing portal、账号删除。

## 四、系统怎么说话（Microcopy）

### 11. 错误文案 = 发生了什么 + 下一步 `copy`

**是什么**：禁止裸 `An error occurred` / 内部错误码甩给用户。  
**为何杠杆**：每次报错都是信任投票；说清「怎么办」比漂亮 UI 更能止损流失。  
**怎么落地**：模板：`[具体事实]。[可选原因]。[动作：重试 / 换支付方式 / 联系支持并附 request id]`。  
**反模式**：把 stack trace 给终端用户；所有错误同一句「请稍后重试」。  
**开火路径**：支付失败、权限不足、校验失败、5xx。

### 12. 按钮写后果，不写礼貌 `copy`

**是什么**：`Delete this project forever` / `Yes, cancel my subscription` 优于 `OK` / `Confirm`。  
**为何杠杆**：多几个字，少一次误点心跳骤停；文案即安全护栏。  
**怎么落地**：主按钮 = 动词 + 对象 + 不可逆时加 forever/cannot undo。  
**反模式**：红按钮写「确认」却不知确认什么。  
**开火路径**：破坏性 modal、checkout、权限授权。

### 13. 空状态 = 教程 + CTA，不是「暂无数据」 `frontend` `copy`

**是什么**：空列表写清「这里将来是什么」+ 一个可点主 CTA + 一句有品牌口吻的话。  
**为何杠杆**：高手把空状态当激活漏斗的一环；新手当 bug。  
**怎么落地**：1 主 CTA + 1 示意图或短例 + 可选次要「查看文档」。  
**反模式**：只有插画没有动作；三个同等 CTA 抢焦点。  
**开火路径**：首次进入模块、过滤结果为空。

## 五、信任：暴露可控，比假装完美更便宜

### 14. 公开 Status Page `ops` `growth`

**是什么**：Better Uptime / Instatus / 自建一页，展示组件状态与事故说明。  
**为何杠杆**：反直觉——愿意公开故障的产品显得更可控；B2B 采购常直接问。  
**怎么落地**：监控关键 URL + 支付 webhook；事故时写人话时间线，不是「正在调查」糊弄。  
**反模式**：状态页永远绿但产品明明挂了（信任一次烧完）。  
**开火路径**：营销站页脚、客户成功话术、事故沟通。

### 15. 人话 Changelog，当活着的证明 `growth` `ops`

**是什么**：每周/每两周用人话写「做了什么、为何」；不是 git log 倾倒。  
**为何杠杆**：产品仍在维护的信号；邮件/RSS 是廉价再激活触点。  
**怎么落地**：每条 PR 或每周五写 3–5 条用户语言；订阅可选。  
**反模式**：内部代号、无用户价值的重构流水账。  
**开火路径**：应用内「What's new」、邮件、公开 `/changelog`。

### 16. 事务邮件走接近纯文本 `copy` `growth`

**是什么**：收据、密码重置、发票——像真人邮件，少花哨营销 HTML。  
**为何杠杆**：送达率与「这是办事不是轰炸」的感知；Stripe / Basecamp 系长期如此。  
**怎么落地**：Resend / Postmark；必须 HTML 时也提供干净纯文本 part；品牌克制。  
**反模式**：收据里塞三张促销 banner。  
**开火路径**：支付成功、发票、安全通知。

## 六、分发与定价（只留高信号）

### 17. 分享链接的动态 OG 图 `growth`

**是什么**：每篇内容 / 每个公开页一张定制 OG（`satori` / `@vercel/og` / CF Workers 绘图）。  
**为何杠杆**：链接在 X/Slack/微信展开时的封面，几乎决定点不点；默认截图等于浪费展示位。  
**怎么落地**：模板：标题 + 品牌色 + 关键数字或作者；缓存生成结果。  
**反模式**：每页随机渐变无信息；图上字多到缩略不可读。  
**开火路径**：博客、公开报表、分享页、文档站。

### 18. 定价三档：锚定要诚实 `growth`

**是什么**：低 / 推荐（标 Most Popular）/ Enterprise（Contact us）——用对比降低决策成本。  
**为何杠杆**：锚定与诱饵是真机制；但「所有 SaaS 必须三档」是 cargo cult。  
**怎么落地**：中间档对应你真正想卖的；功能差异用用户语言；企业档写清触发条件（SSO、发票、SLA）。  
**反模式**：两档硬凑第三档垃圾套餐；「最受欢迎」无人选还硬标。  
**开火路径**：`/pricing`；已有付费意向流量时再打磨。

### 19. 「Powered by」只在可分享产物上 `growth`

**是什么**：用户对外分享的页面/表单/小部件底部自然水印。  
**为何杠杆**：零付费渠道的展示位；前提是不违和、可关掉（付费去标）。  
**怎么落地**：分享页 footer 一行；付费计划可移除。  
**反模式**：私密 B2B 后台每页强塞水印（惹厌恶、无传播）。  
**开火路径**：公开表单、文档站点、客户门户分享页。

### 20. 等待名单「分享插队」——仅冷启动 `growth`

**是什么**：分享链接可提前解锁或加积分。  
**为何杠杆**：把获客成本转成社交货币；产品未验证时有用。  
**怎么落地**：唯一 referral code；防刷（同设备/同 IP 限额）；说清奖励。  
**反模式**：已有稳定付费后还靠插队制造饥饿感（透支信任）。  
**开火路径**：预发布落地页。

## 七、专业手感（按产品选型，不是标配教条）

### 21. Cmd/Ctrl+K：密度够再做 `frontend`

**是什么**：命令面板跳转、搜实体、跑高频动作。  
**为何杠杆**：对每日使用的 B2B/工具型产品，是「这团队懂我」的信号；实现可用 cmdk 等，成本不高。  
**怎么落地**：先覆盖导航 + 3–5 个最高频命令；模糊搜标题即可。  
**反模式**：内容站/一次性落地页硬上 Cmd+K；面板里塞从未用过的命令。  
**开火路径**：日活工具、后台、IDE 类产品。

### 22. 微反馈三档（手感纪律） `frontend`

**是什么**：≤100ms 按下态；≤300ms 面板过渡；≥1s 必须给进度（骨架/文案/条）。  
**为何杠杆**：静默超过约 400ms，用户开始怀疑「点没点到」。  
**怎么落地**：全局约定；长任务复用条目 3。  
**反模式**：300ms 动画拖所有点击；无障碍用户未提供降级。  
**开火路径**：全站交互基线。

#### 22A. 交互意图分层：预览、固定、进入 `frontend`

**是什么**：尽量让用户以最低成本逐层表达意图：`hover / focus` 预览或展开，`click / Enter` 固定当前状态，`double-click` 进入编辑态或完整页面；触屏保留一眼可见的 tap / 更多操作入口。不是「能 hover 就绝不 click」，而是把轻意图留给轻动作，把高承诺动作留给明确输入。

**为何杠杆**：用户不用在「进去看看—发现不对—退回来」之间反复付导航成本，也不用先理解整套信息架构；同一对象从扫一眼、停下来到深入处理，心智模型连续。

**怎么落地**：
1. hover 与键盘 focus 展示同一份预览；离开容错 + 退出动画的**总时间控制在 120–250ms**（如 100ms 意图缓冲 + 90ms 淡出），并用连续 hover 区覆盖触发器到预览之间的空隙，避免闪退。
2. 对「预览型对象」，click 固定预览，再点关闭；Enter 与 click 同义。Space 只用于原生 button，不拦截 link / 表格行的滚动与默认语义。对只有一个公认默认动作的对象，click / Enter 可直接执行该动作，不再额外造固定态。
3. double-click 只用于可逆、可预期的「深入」动作，如标题原地编辑、侧栏扩成完整页。单击必须是双击的兼容前缀（先固定侧栏、再扩成整页），不能先做一个随后要撤销的动作；若单击与双击互斥，就不要复用同一热区，改用显式展开按钮或快捷键，禁止靠 300ms 单击延迟仲裁。
4. 任何 double-click 都必须有可发现的替代路径（展开 icon、上下文菜单、快捷键或预览内按钮），不能成为唯一入口。键盘从固定预览进入深层页面，走预览内首个命名清楚的动作或约定快捷键（如 `E` 编辑），完成后把焦点落到标题 / 编辑框；关闭后焦点还给触发器。
5. 触屏不得依赖 hover / double-tap 猜谜：tap 固定预览或执行唯一默认动作；深入操作使用预览内常驻按钮或「更多」菜单。
6. destructive、付费、权限提升、外部发布等高风险动作绝不由 hover 或 double-click 直接提交，仍需命名清楚的显式动作与必要确认。
7. aria-label / tooltip 说清默认动作；若单击与双击并存，tooltip 直接写「单击侧栏，双击完整页面」。触发器使用真实 button / link 语义，并按状态提供 `aria-expanded`、`aria-pressed` 或 `aria-current`；预览进入合理的 Tab 顺序。焦点、选中、展开、编辑必须是不同的可观察状态，tooltip 不是触屏的唯一说明。
**反模式**：hover 即改数据；桌面有预览、键盘只有跳转；为了识别双击把所有单击硬延迟 300ms；用户单击先打开弹窗、双击又留下闪烁残影；移动端把关键动作藏进不存在的 hover。

**开火路径**：Dashboard 活动流、工作区名称、Agent 侧栏 / 完整页、节点图详情、密集表格行。

#### 22B. 连续性动效：让变化有来路，不让任务等动画 `frontend`

**是什么**：能表达空间、层级或因果关系的状态变化，优先用短促的淡入淡出、缓入缓出、渐隐渐现；侧栏、卡片归位、跨容器移动可用轻弹性。动效是「刚才的对象去了哪里」的视觉语法，不是给每次点击加表演。

**为何杠杆**：直切容易让用户误以为内容被替换、丢失或跳到了别处；连续过渡保留对象恒常性，降低重新定位成本。

**怎么落地**：
1. Starter token：`--motion-press: 80ms`、`--motion-tooltip-in: 140ms`、`--motion-tooltip-out: 90ms`、`--motion-panel-in: 220ms`、`--motion-panel-out: 160ms`；进入用 `--ease-out: cubic-bezier(.16,1,.3,1)`，退出用 `--ease-in: cubic-bezier(.4,0,1,1)`。按下反馈仍须 ≤100ms、面板 ≤300ms；同一层级共用 token，不在组件里各写一套。
2. 默认只动画 `opacity` 与 `transform`。高度变化若已有测量/过渡能力就复用，否则宁可即时布局 + 子内容淡化，不为一处折叠引入脆弱的 layout 动画。弹性只给真实位移或归位，而且优先复用现有 spring；没有现成 motion runtime 就使用 ease-out，不为「弹一下」新增依赖。文字、颜色和错误提示不要弹跳。
3. 先响应用户，再播放过渡。路由、侧栏扩页、列表重排**可以**用 View Transitions 或等价渐进增强，不是入场门槛；动画失败时功能必须照常完成，焦点必须落到新上下文。
4. `prefers-reduced-motion: reduce` 下关闭弹性、大位移、视差和循环动画；必要状态变化改为 ≤100ms 淡化或直接切换。不要靠 UA / 核心数猜「低端设备」；只有已有性能监测确认持续掉帧，或浏览器给出明确节省偏好时，才启用无动画降级，否则保持实现简单。
5. 进入与退出都要可中断；快速重复操作以用户最后一次意图为准，不排队播放陈旧动画。
**反模式**：把「避免直切」理解成所有东西都慢 300ms；退出动画阻塞保存或导航；每张卡都 bounce；用动效掩盖加载、错误或真假数据切换；忽略 reduced-motion；动画结束后焦点仍留在消失的元素上。

**开火路径**：侧栏开合与扩页、hover 预览、原地编辑、图节点详情、列表重排、Tab / 路由上下文切换。

#### 22C. 双轨披露（Duplicated disclosure） `frontend`

**是什么**：同一个事实被渲染进两个内容区域：触发器内嵌一段"裁短的预览"（hover/focus 透出的 ghost 文案），真正的完整内容又在点击后的披露体（`<details>` 正文 / expanded region）里第二遍出现。两个区域背后各挂一套状态：CSS `:hover` / `:focus-within` 与原生 details toggle / `aria-expanded` 是两个独立状态机。硬门槛一句话：**一个事实 → 一个内容区域 → 一个真源 → 一个披露状态机**。这不是 22A 的分层意图——22A 是同一区域用低承诺动作逐层展开；本条是"看似分层，实为两块平行真相"。

**为何杠杆（为何要禁）**：诱惑在于"预览显得信息密度高、hover 一眼聪明"。真实成本五笔：
① 同一段文案两份 DOM，文案一改必须改两处，注定漂移；
② 两套状态机永远可能同时为真——生产事故里：点击（展开）时 summary 仍带 focus-within/悬停，ghost 预览与完整正文同时可见，用户读到同一句话两遍；
③ 指针路径（hover 有预览）与触屏路径（`pointer: coarse` 没有预览，tap 直接切换正文）行为不一致，同一交互在两类设备上学到的是两种规则；
④ 预览是被截断的 slice（源里常见 `answer.slice(0, N)` 这类硬编码长度），真源一改长度就失同步；
⑤ 可达性面与测试面爆炸：hover/focus/open 状态组合 × pointer/keyboard/touch × reduced-motion 全要过一遍，却没有一个叙事解释"这两块为什么同时存在"。
删掉 ghost 区后，行为、测试、文案三者同时归一——这才是四两拨千斤的反方向：省掉的是负杠杆。

**怎么落地**：
1. 只渲染一份事实：正文进唯一的披露体，触发器（summary / button）只换代告(current) + `aria-expanded`（原生 `<details>` 自带）。
2. hover/focus 是**同一个披露体的打开信号**，与 click/tap/Enter 写同一个状态机；pointer-leave/blur 是它的关闭信号（若用户已显式 open 则不收回）。
3. 优先级预防抖动：显式 toggle（click/tap/Enter/Space）> hover/focus 进入；显式关闭 > 悬停离开；触发器到披露体之间覆盖连续 hover 区，穿过空隙不得闪关。
4. 触屏：tap = 同一区域 toggle，durable；绝不依赖 hover 通道交出信息。
5. 降低用户跳跃优先：hover/focus 提前打开**那个披露体本身**（不另造 ghost 文案区），pointer-leave 立即收回；click/Enter 把同一披露体固定为 durable open（`pinned` 只有显式 close 能解）。

**Bad**（匿名化真实事故：FAQ 预览 28 码点 + `<details>` 正文）：

```html
<details class="faq">
  <summary>
    问题
    <span class="preview" aria-hidden="true">答案前 28 码点…</span> <!-- ghost 区 -->
  </summary>
  <p>完整答案</p> <!-- 真源区 -->
</details>
```

```css
@media (pointer: fine) { .preview { display:inline; opacity:0 }
  .faq:hover .preview, .faq:focus-within .preview { opacity:1 } }
/* click → <details> 原生 toggle → open 时 preview 与正文同屏共存 */
```

**Good**（唯一区域 + 单一状态机）：

| 事件 | closed | open（无 pinned） | open（pinned） |
|---|---|---|---|
| hover/focus 进入 | open 立即 | 保持 open | 保持 open |
| pointer-leave/blur | 保持 closed | close（立即） | 保持 open |
| click / tap / Enter / Space | open 且 pinned | open 且 pinned | close |
| 显式关闭动作 | （无） | close | close |

一行状态机：`closed —(hover/focus/click/pinned? open)→ open —(无 pinned 且 pointer-leave/blur? close)→ closed`；pinned 只由显式 click/Enter 设立，也只由显式动作解除。

**检查清单 / lint 口问**：
- 这一事实在 DOM 里是不是只出现一次（没有 slice/预览/tooltip 文案的第二份拷贝）？
- preview 和正文是不是**同一个**状态变量驱动的同一个区域？hover+click 同时生效时会不会两块都可见？
- 触屏有没有独立可推断的路径，还是暗示了不存在的 hover？
- 有没有硬编码长度（如 slice 28）只出现在预览侧？真源一改长度，预览会不会先碎（漂移先兆）？
- collapsed 提示和 expanded 正文是否互斥而非并成（如果两者可同时可见 than it's a two-region bug）？

**生产反面示例（匿名化真实事故）**：公开营销长页 FAQ（原生 `<details>` + summary 内 28 码点 ghost 预览行，hover/focus-within 透出预览、click/Enter 展开正文）。点击展开时 summary 仍处 focus-within，预览与正文同屏；触屏用户永远见不到 hover 提示；文案改动需要在模板里维护两处字符串。修复即本条：删 ghost 区，hover/focus 与 click 全部写进同一个 disclosure 状态机，行为、测试、文案同时归一。

**开火路径**：FAQ/disclosure/accordion、卡片 peek 预览、summary+detail 组合、任何"顺手加一个 hover 预览行"的评审现场；见到"触发器内嵌被截断的正文 slice"停下过审本条。

### 41. 铺底禁纯白纯黑（色/面偏好指针） `frontend` `copy`

**是什么**：page / card / sidebar / popover / sheet 铺底禁 `#FFF`×`#000`（含 α≥0.85 纯白盖浅底、纯黑正文）；按场景二选一：A 微色相壳（营销壳/短会话）或 B 米黄纸（盯表长会话）。数字、证据与杀掉标准只维护专文：[`design-color-surface-preferences.md`](./design-color-surface-preferences.md)——本条只留禁令与指针，不抄数字。  
**为何杠杆**：纯白纯黑是没调过色的浏览器默认，也是显示器能给的最大刺激，盯表刺眼；改一组 token 一杯咖啡。  
**开火路径**：日用后台、OA、阅读面、新项目 `:root` 立项时；营销极简页是例外不是默认。

### 42. 卡片顶部彩色「上盖条/错位浮层」是 AI-slop 强信号 `frontend`

**是什么**：不做这种识别度很高的假深度边界：给卡片加一个彩色 `border-block-start: Npx solid` 顶条，或叠一层向后错位几像素的同色「offset layer / peek」，靠暴露的色块假装边界和层级。真层级只用一种诚实手段：整理好的 1px edge、内嵌分隔线、侧轨（side rail）、缺口（notch）、留白节奏、字重层级，或交互状态本身（selected/hover 就够）。
**为何杠杆**：一眼识别低成本 pro 样式 vs 「AI 组装感」；侧轨/内分隔同样 3 秒可感知，还不会和状态色打架。
**怎么落地**：① 状态或类型的 accent 只放 `border-inline-start` 3px 侧轨或 icon/字体色；② 层级靠表面色（body/surface/muted 三档）与阴影渐弱；③ 顶条冲动出现时先问「上面那条想说的信息能否用 eyebrow 文案讲出来」。
**反模式**：每个状态一个颜色顶条（orange top slab）；错位浮层假装「另一块卡伸出来」却无任何语义；多个嵌套卡各自再带顶条；与选中态无关的橙色只为了「好看」。
**开火路径**：仪表盘节点图、状态卡、看板卡片、 swarm of feature cards；见到「colored top slab + peeking offset layer」的组合先整块停工审查。

## 八、后端：不炫技的稳定

### 23. 幂等键（Idempotency-Key） `backend`

**是什么**：支付、下单、发码、扣额度——客户端带 UUID，服务端同键同响应。  
**为何杠杆**：网络重试不再变重复扣款；Stripe 式 header 是行业默契。  
**怎么落地**：存 `key → response` 24h；业务唯一约束作双保险。  
**反模式**：只幂等「创建订单」却不幂等「扣配额」；键用可猜测自增。  
**开火路径**：Checkout、webhook 处理、短信/邮件发送。

### 24. 队列：最便宜的架构升级 `backend`

**是什么**：发信、缩略图、webhook、AI 长任务移出 request-response。  
**为何杠杆**：接口 p99 与错误面立刻缩小；用 BullMQ / SQS / Postgres `SKIP LOCKED` 皆可。  
**怎么落地**：先拆「失败可重试且用户可稍后见结果」的副作用。  
**反模式**：所有逻辑进队列导致调试地狱；无死信与告警。  
**开火路径**：注册后发信、导出、第三方推送。

### 25. Feature Flag = 灰度 + 熔断 `backend` `ops`

**是什么**：DB 一张表或 Unleash 等；按用户/百分比开闭。  
**为何杠杆**：出 bug 不靠紧急重新部署；小团队的「后悔药」。  
**怎么落地**：新危险路径默认 off；准备一键全关。  
**反模式**：flag 永不删除变成永久分叉；用 flag 代替真正的设计决策。  
**开火路径**：支付改版、新权限模型、实验 UI。

### 26. 迁移纪律：先加后删、CONCURRENTLY `backend` `ops`

**是什么**：生产加索引用 `CREATE INDEX CONCURRENTLY`；列变更向后兼容（先加列双写，再切读，后删旧）。  
**为何杠杆**：零停机的核心是 DB 纪律，不是 K8s 玄学。  
**怎么落地**：迁移脚本进 CI；危险迁移写 rollback 笔记。  
**反模式**：直接删列、锁表加索引、大表同事务建索引。  
**开火路径**：每次 schema 变更。

### 27. 第三方调用：熔断 + 退避 `backend`

**是什么**：连续失败则短暂停呼；重试指数退避 + jitter。  
**为何杠杆**：一个支付/邮件/LLM 挂掉不应拖垮你全站线程与账单。  
**怎么落地**：超时明确；半开恢复；用户侧有降级文案。  
**反模式**：无限重试打爆对方与自己；吞掉错误当成功。  
**开火路径**：Stripe、邮件 API、模型推理、地图服务。

## 九、七天内能改决策的分析（反对虚荣仪表盘）

### 28. 只埋 5 个「能改下周优先级」的事件 `ops` `growth`

**是什么**：例如：`signed_up` → `activated`（你定义的 Aha）→ `key_action_weekly` → `checkout_started` → `paid`。  
**为何杠杆**：六个月后想问「谁用了 X」只能靠当初；但埋 200 个没人看的事件等于没埋。  
**怎么落地**：PostHog / 自建 events；每事件写清「若下降，我们下周改什么」。  
**反模式**：虚荣 DAU 大盘；无 activation 定义就优化文案。  
**开火路径**：产品第 1 周；每个新功能只加 1 个成功事件。

### 29. Session Replay 只看激活漏斗 `ops`

**是什么**：OpenReplay / 同类工具，抽查看用户卡在哪。  
**为何杠杆**：比问卷更接近真实挫败；用于修 onboarding，不是偷窥一切。  
**怎么落地**：采样；打码密码与 PII；只播「未激活」会话。  
**反模式**：全量录制无隐私政策；团队当娱乐看戏。  
**开火路径**：激活率停滞、某步高退出。

## 十、1–3 人运维节奏

### 30. `clone && make dev` 一条命令 `ops`

**是什么**：Docker Compose / 脚本把依赖、env 示例、迁移一次拉起。  
**为何杠杆**：未来的你（或兼职协作）30 分钟能开工；文档负债立刻下降。  
**怎么落地**：README 顶部三行：是什么 / 怎么跑 / 文档在哪。  
**反模式**：README 小说却跑不起来；秘钥写进仓库「示例」。  
**开火路径**：任何会活过下个月的项目。

### 31. 结构化日志 + Request ID `backend` `ops`

**是什么**：`logger.info({ event, userId, requestId })`；禁止无法检索的字符串散文。  
**为何杠杆**：小团队没有专职 SRE；一个 ID 贯穿日志/支持回复，是最便宜的可观测性。  
**怎么落地**：中间件生成 UUID，下传队列与外部回调。  
**反模式**：在日志里打 token/密码；只有 `console.log`。  
**开火路径**：所有 API 与 worker。

### 32. 安全基线：Headers + Rate limit + Secrets 不进 git `ops` `backend`

**是什么**：HSTS / CSP 基线 / `nosniff`；登录与 API 限流；Doppler/1Password/平台 Secrets。  
**为何杠杆**：10 分钟配置挡掉一整类低级事故；限流首先保护你免于自己的 bug 与账单爆炸。  
**怎么落地**：CF / 反代一层限流；`securityheaders.com` 扫到可接受；CI 扫密钥。  
**反模式**：CSP 严到产品不可用却不迭代；限流只防外人不管内部循环。  
**开火路径**：任何公网服务上线前。

### 33. 客户端校验 = UX；服务端再校验 = 安全 `backend`

**是什么**：价格、权限、优惠、数量——服务端必须重算。  
**为何杠杆**：十年老话，每周仍有人忘；支付边尤其致命。  
**怎么落地**：前端为了体验预检；后端权威；关键写路径单测覆盖篡改。  
**反模式**：信前端传来的 `price` / `role`。  
**开火路径**：Checkout、权限变更、优惠码。

---

## 十一、AI 产品：非显而易见的廉价赢

### 34. Token 流式输出 `frontend` `backend`

**是什么**：首字节尽快流式渲染，而不是等整段生成。  
**为何杠杆**：TTFT 体感决定「快还是死机」；与条目 3 的阶段文案可叠用。  
**怎么落地**：SSE / fetch stream；可停止生成；失败保留已生成部分。  
**反模式**：假打字机效果掩盖已完整返回的结果（用户识破后掉信任）。  
**开火路径**：聊天、长文生成、代码助手。

### 35. 引用工作过程与产物 `copy` `frontend`

**是什么**：展示用了哪些来源、中间提纲、将写入的文件/字段——让结果可审计。  
**为何杠杆**：AI 幻觉的信任解法不是「我们很准」，而是「你可以核对」。  
**怎么落地**：来源列表可点开；写操作前 diff 预览。  
**反模式**：虚假引用；引用不可点。  
**开火路径**：RAG 问答、自动改数据、代理执行。

### 39. 两段式激活：Onboarding → Setup `growth` `frontend`

**是什么**：先用最小努力送到个性化 aha，再引导生产用量（接真数据/真渠道）；不要把两者揉成「大配置向导」。完整手册：[`ui-patterns/saas-onboarding-two-phase.md`](./ui-patterns/saas-onboarding-two-phase.md)。  
**为何杠杆**：空白 Dashboard 与 20 字段问卷杀死激活；「像为我做的、已经有用」后再谈集成，付费教育也更顺。  
**怎么落地**：定义可测 `aha_reached`；标识输入（域名/URL/账户）→ 劳动幻觉分析 → 可玩结果 + 升级预览 → 单一 CTA 进 Setup；Setup 里程碑必须是 usage 不是勾选。  
**反模式**：未 aha 先锁支付；个性化失败整页死锁；用配置完成 % 冒充激活。  
**开火路径**：B2B SaaS、agent 产品、出海云类控制台首登。

## 十二、判断层：最大的杠杆是不做

### 36. 杀功能 / 杀细节的标准 `ops`

**是什么**：每季看使用数据；长尾功能、无人感知的动效、从未打开的设置——删。  
**为何杠杆**：代码与认知是负债；20% 功能常扛 80% 价值（经验法则，不是精密定律）。  
**怎么落地**：60 天无用 → 标记废弃 → 下线路径 + changelog 一句。  
**反模式**：因为「做都做了」而永久抚养。  
**开火路径**：路线图会、技术债日。

### 37. 两扇门（Bezos）：可逆就快跑 `ops`

**是什么**：单向门（定价模型、数据删除、品牌承诺）慢决策；双向门（文案、布局、实验 flag）快试。  
**为何杠杆**：小团队用「委员会流程」处理双向门，是效率灾难。  
**怎么落地**：PR 描述写一句「这是哪扇门」；单向门才拉多人。  
**反模式**：一切等齐人；或一切拍脑袋上生产不可逆。

### 38. Boring tech 与 YAGNI 预算 `ops` `backend`

**是什么**：创新预算花在业务差异；默认 Postgres / 熟悉框架；不为「未来可能」抽象。  
**为何杠杆**：Dan McKinley「Choose boring technology」——复杂度是税。  
**怎么落地**：新依赖要回答「没有它哪件事做不成」；抽象等到第二次重复。  
**反模式**：六个专用存储「微服务」服务 200 用户。

## 附 A · 工作示例：Premium One-pager 组合拳

> 这是**原则的示例包**，不是全手册的重心。适合营销长页 / 文档叙事页；B2B 后台不必照搬。

一次下午可装上的五件套，共同服务「我在哪 / 有反馈 / 有质感」：

1. **顶部 3px 滚动进度条**（渐变细线随滚动生长；可内嵌纸纹 soft-light）— 位置确定感  
2. **进视口 reveal 一次**（淡入 + 上浮 ~22–44px，不反复跳）— 节奏感  
3. **右侧章节点 / 固定舞台章节指示器**（衬线页码、当前章节名；浅底深墨或纸底衬）— 结构感  
4. **Paper Shaders 双层材质 veil**（真纸纹 + Perlin 噪点，multiply 极低透明；可动图层）— 材质感  
5. **细滚动条 + `::selection` + `scroll-behavior: smooth` + `prefers-reduced-motion` 降级** — 完成度

落地纪律：动画可关；动效不超过内容本身；不要把组合拳拆去每个 SaaS 表格页复读。

### texture 材质包（Paper Shaders 系） `frontend`

**是什么**：来自 [Paper Shaders](https://shaders.paper.design/) 的零依赖 shader 纹理（纸纹、Perlin/Simplex/Neuro 噪点等），导出 static webp/png 或 data URI；全页两层 `fixed` 覆盖（multiply + 极低透明度）。静图也可「活」——动的是图层 `transform`，不是文件本身。
**为何杠杆**：一杯咖啡成本兑现「有质感 / 手作感」，比自绘网格渐变便宜一个数量级；机制可迁移到任何低彩度纸/墨叙事页与 HTML deck，不绑某一品牌皮肤。
**怎么落地**：
1. Fetch `paper-texture` + `perlin-noise`（或等价噪点）；单文件交付时 base64 内联（纸纹 ~88KB raw 可接受）。
2. 两层 veil：`position:fixed; inset:0; pointer-events:none; z-index` 低于 UI、高于舞台底。子层 `inset:-3%` 给漂移留边；`background-size: 640px 480px`；`mix-blend-mode: multiply`。
3. **已验证透明度（lizliz deck 2026-08）**：纸纹 **0.085**、噪点 **0.05**。可用区间约纸纹 0.03–0.085、噪点 0.02–0.05；逼近上限必须截图验正文对比度。
4. **动效（四两拨千斤）**：纸纹 `tex-drift` — `90s linear infinite alternate`，`translate3d(-26px, 14px, 0)`；噪点 `tex-grain` — `3.4s ease-in-out infinite`，多关键位胶片抖动（约 ±7px）。两层 `will-change: transform`。配套微交互共用 `--ease-out-expo: cubic-bezier(0.16,1,0.3,1)`：列表行 hover `translateY(-2px)` + 轻影（0.24s）、面板 hover 可走横向 `translateX(4px)`、active 压下 0.08s、进场 reveal `translateY(22px)` 与翻页叠加。
5. 进度条（可选）：3px track + N 等分刻度；fill 内 `::before` 叠纸纹 `mix-blend-mode: soft-light`。
6. 固定舞台章节指示器（可选）：纸色底衬 + 深墨字（跨浅/深幻灯片都可读）；章节名 `word-break: normal; overflow-wrap: normal` + 最多两行 clamp——禁止单词/英文 token 正中断行。
7. 全部动画：`@media (prefers-reduced-motion: reduce) { … animation: none; transform 交互关闭 }`。
**反模式**：把 0.085 当装饰默认值往上加（过线立即糊字）；只写「>0.08 禁」却不截图验收；waves/大位移动效不做 PRM；把 `.flow-step` 与 `.panel` 写成同一套 hover 轴（实战里纵移/横移分工）；章节指示器浅字贴浅底、或 `word-break:break-all` 把章节名撕开；每个后台表格页都铺——组合拳只给叙事页 / deck。
**开火路径**：下午装——Paper Shaders fetch → 双层 veil CSS（对参：纸 0.085 / 噪 0.05 / drift 90s / grain 3.4s）→ 进度刻尺 → 右中章节指示器（纸底衬 + 深墨 + 禁中断行）→ 微交互 kit → PRM；验收：1280×720 截图正文不被糊、指示器在深浅页都可读。

## 用法（写进团队约定）

1. **别煮海**：一次只挑 3–5 条，进本周节奏。  
2. **先定义成功信号**：例如「支付重复投诉」「激活率」「支持工单里的『我点了没反应』」。  
3. **做完再测**：前后对比同一信号；没动信号就回滚或降级。  
4. **机制可迁移，清单条目不可宗教化**——Cmd+K、三档定价、one-pager 动效都有「不适合」的时候。

一句话：高杠杆细节的本质不是审美，是**廉价兑现承诺感**——在用户不确定的瞬间，让他觉得「这东西在替我兜底」。这就是四两拨千斤。
