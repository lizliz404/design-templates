# ReplyArc 对 CFE 的启示（只记录，本轮不实施）

前提：CFE 用 Astro 加 React 岛，UI 用 Base UI、shadcn/ui、Tailwind 和 Iconoir；数据在自己的 Worker 和 D1 上；AI 不做承诺，报价交给人。下面只说该学什么、不该学什么，不引入新库。

## 值得学

| ReplyArc 做法 | 为什么有用 | CFE 现状 |
|---|---|---|
| 预设引导问题卡 | 访客不用想第一句问什么 | Ask AI 没有引导卡 |
| 对话中留资（Franklin 式：姓名→邮箱→电话可跳过） | 不跳出聊天就把线索留下 | 聊天带上下文跳到 EnquiryDialog 预填，部分字段会截断 |
| 答不出就承认，再收联系方式 | 把「不知道」变成一条线索 | 已有确定性红线和 human_required，缺「顺手留资」这一步 |
| 主动开口的克制规则 | 只在高意向页面，每次访问一次，打字时不打断 | 没有主动开口 |
| 每条回答标出处 | 访客能自己核对 | 已有 markdown 链接，没有统一的出处样式 |
| 未答问题收集成待补内容 | 内容缺口越补越少 | 没有 |
| 工单号回显 | 访客知道已被受理 | 询价对话框里有 ref |

## 不该学

- 转人工触发太敏感，触发后整条对话锁死、不再回答。
- 频道和预约做成只有展示的入口：CFE 没有真实通道就不放。
- 营销 Logo 墙比真实集成多。
- 企业官网挂「Powered by」角标。
- 只带最近 20 条消息、知识库比官网还浅：CFE 用结构化的产品和文件数据，本来就更扎实。

## CFE 本来就更强的地方

- 确定性的承诺过滤，不靠模型自觉。
- 询价写进自己的 D1，数据自有，没有外部 SaaS 处理访客数据。
- 文件和证书有门槛控制。

## 留给以后决定

- 要不要做聊天内直接提交的询价，而不是跳到对话框。
- 要不要有真人在线通道。如果做，只需要一个共享收件箱加实时通道，不必买 SaaS。
