## A · 顶部菜单滚动行为

**结论：不是常驻 sticky，也不是隐藏/显示二元切换 —— 是「下滑按比例让位、上滑全速带回」的逐帧滚动跟随，可见时底板才长毛玻璃。**

Liz 观察到"往下滑的时候没有菜单"是对的：nav 会完全滑出屏幕，但不是瞬间消失，是以滚动速度一半向上挪。

### 机制（全部参数已核实）

```
let t  = max(0, lenis.scroll || 0)      // lenis animatedScroll
delta  = t - prev
if delta > 0: delta /= 2                // 下滑只记一半速度
scrolledValue = clamp(scrolledValue + delta / navHeight, 0, 1)
navWrapper.y  = -navHeight * max(scrolledValue, hiddenValue)
document.documentElement.style['--header-offset'] = navHeight + navWrapper.y
```
— `app.xxR_cdSYJQ.js`，HeaderDesktop `startRender` 循环（navHeight 实测约 72–90px）。

- **下滑**：每帧把滚动增量的一半计入 `scrolledValue` → 约 144–180px 下滑后 nav 完全移出视口（半速滑走，不是瞬隐）。
- **上滑**：增量全额计入（负方向），约一个 nav 高度的上滑就完全带回 —— 回得比走得快，是刻意的非对称。
- **毛玻璃**：`hasScrolled = animatedScroll > 30`（30px 阈值）或 `linkHovered` → `showFrosted` → `tween({frosted:1, backgroundOpacity}, 300, "easeOutCubic")`。CSS 侧 `.navWrapper:after` = `backdrop-filter:blur(4rem)` + `background:var(--backgroundColor)`，`opacity:calc(var(--frosted)*100%)`（style.css :694-696）。回顶/离悬同样 300ms easeOutCubic 渐出 —— **底板永远渐隐渐显，没有硬切**。
- **配色随 section 变**：`navColorMode` 由当前 section 上报（`ViewController/navState`）—— dark/light/frosted-white = 黑字 + 白玻璃底 `backgroundOpacity:.5`；solid-black = 白字 + 黑玻璃底 `opacity:1`。
- **程序化隐藏**（弹层/转场时整 nav 下场）：`HeaderController/hidden` → `hiddenValue` tween 0→1，**1000ms easeInOutCubic**，与 scrolledValue 取 max —— 两套隐藏机制共用一条 `navWrapper.y`。
- **消费端**：`--header-offset`（= nav 当前露出高度）被 `.open-roles__filters-wrapper{top:var(--header-offset)}` 这类 sticky 元素吃 —— 页内 sticky 永远贴着 nav 实际露出的那条边，不假定它要么全在要么全没。

## B · 图标 morph（Company 加号→减号）

**结论：不是 SVG path morph，是两条 `<div>` 细线，只有竖笔转 90° 躺平盖住横笔 —— 300ms ease-out。「优雅」来自只动一根线。**

```css
.HeaderDesktop .plus-sign{width:.6rem;height:.6rem;position:relative}   /* ≈8.4–9.6px */
.HeaderDesktop .plus-sign>*{background:currentColor;width:100%;height:1.5px}
.HeaderDesktop .plus-sign>:first-of-type{position:absolute;top:50%;left:50%;
  transform:translate(-50%,-50%) rotate(90deg);transition:transform .3s ease-out}
.HeaderDesktop .plus-sign>:last-of-type{position:absolute;top:50%;left:50%;
  transform:translate(-50%,-50%) rotate(0);transition:transform .3s ease-out}
.HeaderDesktop.isCompanyOpen .plus-sign>:first-of-type{
  transform:translate(-50%,-50%) rotate(0)}   /* 竖笔躺平 → 两线重合 = "−" */
```
— style.css :738-745。同款 `.FooterListLinks.isOpen .plus-sign`（移动端 footer 手风琴复用同一 morph，盒 1rem）。

**配套开合编排**（JS，`companyHover` 分支 —— `companyLink.hover(hoverCompany)` + focus/blur，`click` 绑的是空函数：面板实为**悬停/聚焦**触发，不是点击）：
- `menuWrapper.tween({height:0→实测内容高}, 500, "easeOutCubic")` — 容器先拉开；
- `companyWrapper.tween({opacity:0→1}, 500, "easeOutCubic", delay 100ms)` — 内容晚 100ms 淡入；
- 关闭反向但 **opacity 用 1000ms**（内容淡出比高度收起慢一倍）；
- 同时 header `:before` 黑色渐变 scrim（135% 高、14-stop）→ opacity .4；全屏 `.navOverlay`（`backdrop-filter:blur(.5rem)`）opacity→.5，300ms —— 菜单打开时整个页面被按了一层柔焦。

**文字侧**：`Company` 标签本体 = `.companyLinkText`（absolute 压位）+ `.companyLinkTextHidden`（opacity 0 占位），`.company-wrapper{overflow:clip}` —— 与 `.HeaderDomainLink` 的 `.name`/`.hiddenName` + `span{mask-image:var(--maskId)}` 同构（style.css :714-729）。双文本叠放 + clip/mask 换面是他们导航文字的统一手法；另外全域 link hover 时还跑 scramble 文字动画（见 C）。

## C · 动画语言清单（"渐隐渐显"的完整参数）

**结论：三层时长纪律 —— 微交互 300ms / 面板入场 500ms / 场景级 1000ms；缓动基本只用 easeOutCubic，入场大幕换 easeOutExpo，场景移动用 easeInOutCubic。文字不是淡入，是 scramble 解码 + clip 擦除。**

### 文字动画三原语（TextAnimationHelper）

1. `animateText(el, 500ms)` — **scramble 解码**：v 0→1 easeInOutSine，每 ~20ms tick；已落定前缀显示真字，未落定尾部填随机 A–Z（数字串用 0–9），保留空格/`/`/`?`/`,`/`.`，大小写随原文。标签、标题、卡片描述进场全用它（400–750ms）。
2. `animateMask(el, t)` — 逐字打字机，tween 子串长度，easeOutCubic。
3. `animateClip(el, 50)` — clip-path 从左往右擦除 `polygon(0 0,p% 0,p% 100%,0 100%)`，**每个字符 50ms**（7 字 ≈ 350ms），easeOutCubic。

### 入场编排（InView，阈值 .5 = 元素 50% 可见触发）

- 预备：`transform x:-10%; opacity:0` → 进场 `x:0; opacity:1`，1000ms easeOutExpo；
- 列表 stagger：**逐项 +100ms**（`e+100*(n+1)`）；图片元素再 +500ms；
- `ResponsiveImage.loaded`：图片本身 opacity 0→1 只有 **.125s ease-out** —— 图是"闪一下显形"，不拖沓。

## E · 图片处理（"图和文共舞"的实现）

**结论：图没有"框"是因为 (1) 全部 object-fit:cover 裁满、(2) 图底用 multiply 渐变溶进页面底色、(3) 文字要么压图底要么和图共用同一 12 列 —— 从不出现"白底卡片包一张图"。**

- **裁切**：`object-fit:cover` 39 处（vs contain 4）；图片元素 `border-radius:0`（显式方角），卡片最多 2px；`ResponsiveImage` 加载 0→1 只 .125s。
- **出血三档**：
  - 全出血：域页 banner 图、HelloWar、FlagHeader（贴视口边）；
  - grid 内：`mediaContainer{padding:0 2rem}`（ProductHeaderSlice、arsenal、news hero 图 = 左右各 28px 边距）；
  - 分栏：`.ImageColumnSlice.two` = figure 1/7 + 7/13（**非对称 6/6**，three = 4+4+4）。
- **消底 scrim**：`.overlayer` = 14-stop 渐变 transparent→#010101，`mix-blend-mode:multiply;opacity:.5`，absolute 压图底（FeaturedAnnouncementSlice :1644、FeaturedProductsCard :1707）—— 图的下缘直接溶成页面底色，文字压在这个"看不见的底"上，所以读不到框。
- **压字**：`.FeaturedProductsCard .content-wrapper{position:absolute;bottom:2rem;left:1.15rem}` —— title 1.5rem/700 常驻，description 只在 hover 展开（height 0→1.25rem + margin-top .5rem + opacity，250–500ms easeOutCubic；JS animateIn/animateOut）。
- **图注**：`.MediaCaptionBlock` 图下一行 caption 走同一 12 列，分 1/7 + 7/10 + 10/13 三段 —— 图与文字同网相邻而非互相包裹；caption .75rem uppercase #565654。
- **分隔用发丝线不用框**：`.SubdomainMediaSlice .border` = 1px #fff/30% 横线隔开图区与文区。
- **text-on-figure 的唯一常驻形态**：滚动 scrim + 底部小字（11.5–16px 左边距）；大面积标题压图只出现在 WebGL hero（canvas 绘字，不算 DOM 叠层）。

## F · Footer 注意力分配

**结论：右重左空。左 6 列只放 logo 和法律堆；3 组链接全部压右半区；唯一的"动作元素"（邮箱）在右下角。视觉中心 = 右侧链接簇 + 右下邮箱，不是大 logo 也不是 CTA。**

结构（a11y/home.json contentinfo + style.css :564-640）：

```
┌ logo(8rem, absolute 左上) ┐
│ .top: [spacer 占 6 列][Company 2列][Work with us 2列][Social 2列]   ← 链接簇全在右半
│            ↑ wrapper flex column gap 6rem（84px）                    │
│ .bottom: [copyright+6 法律链 .75rem/op.6, span 6]        [Contact 11/13 + 邮箱 1.125rem]
```

- `.Footer` min-height 22rem，padding 3.5rem 0；spacer 宽 = `span(12 − 2×组数)`（JS `n.spacer`），3 组时 = span 6。
- 组内节奏：title `.75rem uppercase opacity .6` → `padding-bottom:2rem` → links `1.125rem/115%`，链间距 `padding-top:.25rem`；每条链带双箭头 icon（两个 svg，`translate(-100%,100%)` ↔ `translate(-100%)` 互换，.3s ease-out 斜向滑入）。
- `.bottom` 左 = `.small-links` 竖排：copyright .75rem uppercase + 6 条法律链 .75rem opacity .6、gap .25rem —— 低对比一行级，不抢戏。
- `.bottom` 右 = `contact-container` col 11/13："Contact" 标签 .75rem op.6 / mb 1.75rem + `contact@anduril.com` 1.125rem —— **全页脚唯一正文档+唯一转化口**，位置在视觉终点（右下）。
- 进场动画：3 个组 title + contact + social title 各 `animateText 400ms` scramble（Footer `onInView`）。
- 移动端：3 组变手风琴（max-height tween .3s + plus-sign morph 复用）。

## CFE 可抄清单（按 Liz 六条反馈映射）

**A · header 滚动**：CFE 现状 sticky 常驻可保留，但抄两条 —— ①毛玻璃底板改成滚过 30px 后 300ms easeOutCubic 渐入（初始完全透明，别一直糊着）；②若要同款让位：scroll-linked rAF，下滑 `delta/2` 累积到 `-navHeight`、上滑全额恢复，不做 class 二元切换；页内 sticky 元素用 `top:var(--header-offset)` 贴 nav 实高。

**B · morph**：8 行 CSS 直接抄（上方 B 节代码块）：1.5px 线高、`rotate(90deg)→0` 单 bar 旋转、`.3s ease-out`、盒 9px。下拉面板：容器 height tween 500ms easeOutCubic + 内容 opacity 500ms **delay 100ms** + 全屏 blur(.5rem) overlay 300ms；关闭时 opacity 给 1000ms 让内容慢退。

**C · 动画语言**：三档收敛——微交互 `300ms cubic-bezier(.215,.61,.355,1)`；面板/入场 `500ms` 同曲线 + 内容延迟 100ms；场景/大幕 `1000ms cubic-bezier(.645,.045,.355,1)` 或 easeOutExpo `(.19,1,.22,1)`。stagger 100ms/项；clip 文字擦除 50ms/字；图片淡入 .125s；下划线 replay 右出左进 .6s（已在 CFE）。scramble 文字只许给 mono 标签（Geist Mono 档），不给正文。

**D · 密度**：首屏 ≤30 词；主张段 ≤25 词、行宽 40–45ch（CFE 容器内 ≈420px 栏）；H1 与说明行之间 ≥6rem；文块 padding-top 敢给到 10–14rem；section 分隔从 {28,42,56,98}px 四档里挑，主分隔用 56/98；正文 15px/120%/−0.01em，标签 12px uppercase +0.03em；想要流式就改 root rem（1440 档 `calc(.416667vw + 10px)`），不去逐处改字号。

**E · 图**：全部 `object-fit:cover` + 方角（最多 2px）；出血两档（全出血 banner / 容器内嵌 28px 边）；压字图底用 multiply 渐变消底（transparent→页面底色，smoothstep 多 stop），不用色块/边框；caption 走同网格分栏（1/7+7/10+10/13）；文压图底 `bottom:2rem;left:1.15rem`，第二行 hover 才展开；图文并排放非对称 4/8 或 5/7 分栏，不用 6/6。

**F · footer**：链接簇右置右半区（3 组 ×2 列），左半只 logo + 法律行；上下区 gap ≈84px；组内 title 10.5–12px uppercase/opacity .6 → 2rem → links 16px；法律行 .75rem op.6 低对比；唯一转化口（CFE 的 RFQ 邮箱/电话）放右下 11/13 列，标签小字淡化 —— 页脚注意力收敛到"右下一件事"，不堆 sitemap。
