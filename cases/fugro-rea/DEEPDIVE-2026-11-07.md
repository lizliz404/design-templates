## 0. 一页结论

- **A**：header 是 `position:absolute`（透明 hero 页）或 `relative`（浅 hero 页）——**永远不是 fixed/sticky，无收缩/隐藏/变形逻辑，滚下去就没了**。滚动后唯一的"常驻顶部"是 sticky Jump-to 锚点条（top:0）。Liz 的观察属实。
- **B**："树状章节" = 三层结构：首页 6 章 TOC → 枢纽/行业页自己的 4-6 章 TOC（+右端橙色 CTA）→ 叶子页（案例/新闻稿）无 TOC。实现 = CMS 书签哨兵自注册 + sticky 条渲染注册表 + IntersectionObserver（rootMargin `0% 0% -70% 0%`，顶部 30% 可见带）scrollspy + framer-motion 数值动画滚动（1.2s，ease `[0.86,0,0.07,1]`）+ 标题 slug 深链 hash。
- **C**：她的判断基本成立，但要拆开——**Fugro 的锚点条本身就很"刻板印象"（等于 IBM/Siemens 式 sticky subnav），不刻板的是"全局 header 不常驻 + 章节命名编辑化 + 1.2s 慢滚"**。降级版建议保留：sticky 锚点条、scrollspy 橙线、右端 CTA、hash 深链、书签数据结构、jump_to 埋点；砍掉：1.2s 自定义滚动、button 假锚点、双层哨兵 div、"无全局 header"决策。进度条 Fugro 没有，是净新增件。
- **D**：首页全文 **361 词 / 8 章**（每章 15–111 词）；行业页 525 词；案例页 1277 词（C/S/O = 389/451/155）。正文 14/16/18px 三档（≥1250 提到 24px），章节标 24px Aktiv 500，H1 Review 36→58→68px。垂直节奏：桌面 section 顶距 48px、无分割线 section 80px、末 section 底距 80px。
- **E**：图片零框——四种图文关系：满幅图层+视差+scrim+文字压图；单张大图+横滑文字轨压图；分栏编辑式（文字列发丝线框 + 图片列）；卡内裸图（object-fit:cover 贴卡片边，无图框无圆角）。从不做"图占位+说明栏"的框式图。

## A. 顶部菜单滚动行为

### 结论

**Fugro header 滚动后直接滚出视口，不存在任何 sticky/fixed/收缩/复活行为。** header 有两种定位形态，都随文档流走：

1. **透明绝对定位**（photo hero 页：首页/行业页/案例页/investors）——`position:absolute`，宽 100%，浮在 hero 上，背景透明，白字反相。
2. **常规文档流**（无 hero 或文本 hero 页，如 /search）——`position:relative`，白底。

两者**都不是 fixed**：往下滚，header 连同 hero 一起消失；此后页面的"顶部常驻件"是 sticky Jump-to 锚点条（`top:0; z-index:2`，见 §B）。Liz 的"往下滑的时候 FUGRO 没带 sticky menu"观察正确。唯一的 header 运行时状态变化是**抽屉开合**（搜索面板/移动菜单打开时 header 底色 transparent→白，450ms ease-in-out 过渡），与滚动无关——全站与 header 相关的 scroll 监听数为 0（`app.js` 仅有的 2 处 `addEventListener("scroll")` 分别属于锚点条和 framer-motion 内部，见 §B4/B6）。

## B. 树状章节叙事 + Jump-to 机制（重点轴）

### B0. 全貌：三层结构

```
L0 首页 (commerceHomePage, anchorNav=true)
   6 章：What we do / Our industries / Case studies / Organisation / Careers / News highlights
   └─ 每章 = 一个 anchorBarBookmark 哨兵 + 一个内容块
        ↓ 点行业卡进二级
L1 枢纽页 /industries (commerceHomePage)          行业页 /industries/energy (industry)
   4 章：Introduction/Energy/Water/Infrastructure    5 章 + 右端橙色 Contact CTA：
   （每章是一个行业导览 section）                      Our view/Case studies/News and Long reads/
                                                     Technical papers/Sub industries
        ↓ 点案例卡进三级
L2 叶子页：caseStudy / pressRelease / webcastPage / hrContent / contentPage
   —— 无锚点条，纯长文（案例页走 meta 轨 + lifeCycle 手风琴 + C/S/O）
```

- L1 证据：`evidence/pages-1440-settle-industries-dom.html`（锚点条 items=Introduction/Energy/Water/Infrastructure）；`pages-1440-settle-energy-dom.html`（5 项 + Contact CTA 按钮）；`pages-1440-settle-case-study-dom.html`（无锚点条，jump buttons=0）。
- **页型开关矩阵**（`app.js` @≈738355–739198，搜 `withAnchorNavigation`）：`anchorNav=true` = commerceHomePage / industry / subIndustry / landingPage / productPage / expertise / mediaOverview / overviewPage / peoplePage / campaignPage / eventPage / countryDetail / countryOverview；`false` = caseStudy / pressRelease / webcastPage / hrContent / contentPage / careerOverview / careerEvents / linkListpage / countryLocationPage。**"二级又有 jump to"= 行业/子行业/landing 层；叶子层刻意不带。**

### B1. "chapter 瞬时浮在最上方"的真相

锚点条不是"出现"，是 **CSS sticky 常驻**：DOM 位置紧贴 hero 之后（`home-1440-cookies-gone-dom.html`：hero `</section>` 后紧跟 `<div class="sc-df9b7af8-0 eHYTEp">`）。页面顶部时它在 hero 下方视口外；滚过 hero 的瞬间因 `top:0` 吸顶——无过渡、无 JS 切换类，"瞬时"感来自 sticky 本身。hero 高 544–672px（`cssom-sheet-1.css:603-612`），大约一屏内完成交接。

### B2. 数据结构与渲染（TOC 从哪来）

**TOC 没有独立配置文件——书签哨兵自注册。** CMS（Storyblok）里编辑只做一件事：在 body 数组中插入 `anchorBarBookmark` 块。首页 body 实测（`evidence/audit/next-data-home.json`，`story.content.body` 12 块）：

```
anchorBarBookmark(What we do) → intro
anchorBarBookmark(Our industries) → imageReelCarousel(3 卡)
anchorBarBookmark(Case studies) → featuredCardGrid(3 卡)
anchorBarBookmark(Organisation) → masonryContentGrid(4 卡)
anchorBarBookmark(Careers) → crossLink
anchorBarBookmark(News highlights) → imageContentCarouselStatic(3 卡)
```

书签 CMS schema（`pages-1440-settle-energy-dom.html` 的 `__NEXT_DATA__` 实测）：

```json
{ "_uid": "0f09c02a-…", "label": "Our view", "component": "anchorBarBookmark" }          // 普通章节
{ "_uid": "52913d42-…", "isCta": true, "label": "Contact", "profile": "" }                // 右端 CTA 槽
// 可选字段：link（外链）、profile（联系人 story → 点开 Marketo 抽屉）
```

渲染链路（`app.js` @≈553977 搜 `shouldRender:eQ`，@≈752364 搜 `rootMargin:"0% 0% -`）：

1. 页面壳 `e8({blok, withAnchorNavigation})`：`withAnchorNavigation=true` 时用 Context Provider 包住全部 body 块，先渲染锚点条 `<ez shouldRender={eQ(body)}/>`，再渲染内容。`eQ` = 存在任一顶层书签（含 `countrySpecificContent` 内嵌书签）才渲染条。
2. 每个 `anchorBarBookmark` 渲染**双层 div**：外层挂 IntersectionObserver ref，内层挂注册 ref（两层同 id）：
   ```js
   // app.js @≈752364
   {ref:o} = og({ rootMargin: "0% 0% -70% 0%",          // ← 关键参数
                 onChange: e => updateBookmark(id, {visible: e, element}) })
   return <div ref={o} id={r.id}><div {...blok} id={r.id} ref={i}/></div>
   ```
3. 内层 div 在挂载时调用 `addSectionElement({id, element, title, isCta, link, profile})` 进注册表（Map，保持 DOM 顺序）。锚点条的 items 就是从这个注册表 filter 出来的（`!isCta` = 导航项，`isCta` = 右端 CTA）。
4. 锚点条自身 `useLayoutEffect` 量自己的高度 → `setOffsetTop(height)`，作为跳转补偿。

### B3. scrollspy（当前章怎么亮）

Provider 状态机（`app.js` @≈546027 搜 `updateBookmark:(e,t)=>`）：

- 每个 section 的可见性 = IntersectionObserver，**rootMargin `0% 0% -70% 0%`**：观测窗砍掉底部 70%，即 section 只有进入**视口顶部 30% 带**才算 visible（观测器带共享 observer 池，`visible = isIntersecting || ratio>0`，app.js @≈178653）。
- activeIndex 决策：
  - 常态：按 DOM 顺序取**第一个 visible** 的 section；
  - 上滚修正：若当前 active 的 section 变为不可见且 `rect.top >= 0.7*innerHeight`（掉出顶部带向下），active 回退为注册表中的**前一个** section；
  - `window.scrollY === 0` 时 activeIndex 置空（回到页顶无高亮）——锚点条唯一的 scroll 监听（`app.js` @≈551206 搜 `0===window.scrollY&&m`）。
- 效果：当前章按钮变橙 + 2px 橙下划线（见 B6），**章名常驻吸顶条 = Liz 说的"chapter 浮在最上方"**。

### B4. 跳转（点了发生什么）

`app.js` @≈550847 搜 `event:"jump_to"`：

```js
y = (id, title, setActive=true) => {
  const target = registry.find(t => t.id === id)?.element;
  analytics({event: "jump_to", jump_to_text: title});     // 埋点
  scrollTo(target, {duration: 1.2, offset: barHeight});    // ← 1.2s
  setActive && pushHash(slugify(title));
}
```

滚动实现（`app.js` @≈545663 搜 `ease:(null==a?void 0:a.ease)||i||[.86,0,.07,1]`）：目标位置 = `scrollY + rect.top - barHeight`，用 framer-motion `animate()` 驱动一个 motion value 从当前值到目标值，`onChange` 里逐帧 `window.scrollTo(0, v)`。**duration 1.2s（点击跳转）/ 默认 1s；ease `[0.86, 0, 0.07, 1]`**（= cubic-bezier(0.86,0,0.07,1)，强 easeInOutExpo 感）。跳转落点补偿 = 锚点条实测高度（桌面 64px），section 顶边正好贴条底边。

### B5. 深链（URL hash）

- slugify（`app.js` @≈192446 搜 `function eW(`）：`title.toLowerCase().trim().replace(/[^a-z0-9]+/g,"-")` → "What we do" → `#what-we-do`。
- 点击跳转后 `router.push({hash}, shallow)`；挂载时若 `location.hash` 匹配某章 slug，自动滚过去（只执行一次）。
- 注意 a11y 瑕疵（TEARDOWN §9 已记）：TOC 项是 `<button>` 不是 `<a href="#id">`，键盘可达但无语义目的地——CFE 抄时用真锚链。

## C. 评估：Fugro 这套"好但不直观"吗？CFE 降级版怎么切

### C1. 对 Liz 判断的核实

**成立的部分：**

1. **全局导航不常驻是真实代价**。滚过 hero 后，logo/六项导航/搜索/Get in touch 全部消失，一屏只剩章目录。B2B 采购者在任意滚动位都想答"这是谁/怎么联系"——刻板印象（sticky header）存在即合理。Fugro 敢这么做，靠的是页尾必有专家名片 + 每个内容件自带出口（见 TEARDOWN §7 的 CTA 密度），CFE 内容密度到不了那个程度。
2. **章节命名编辑化**（"Our view"、"Organisation"）不预测内容，第一次来的人不知道点开是什么。刻板印象命名是功能性的（"Products / Capabilities / Projects"）。
3. **1.2s 自定义滚动太慢**——是"设计感"件不是"效率"件，快滚预期是 300–500ms。
4. **树深三层、每层各自 TOC**，要求访客脑内建站图；真实 B2B 行为是 pogo-stick（搜索→着陆→退回→再着陆），树只在"顺着首页往下读"这一条路径上成立。

**不完全成立的部分**：sticky 锚点目录条本身**就是** B2B 刻板印象件（IBM/Siemens/ABB 长页全是 subnav + scrollspy）；Fugro 只是把"全局 header 常驻"换成了"章目录常驻"。所以 CFE 不需要发明"刻板印象友好版"——只需要**把 Fugro 的锚点条装回标准 B2B 顶栏结构里**。

### C2. 降级版取舍清单（映射到反馈 C）

**保留（机制值得抄，成本/收益比高）：**

| 机制 | 理由 |
|---|---|
| sticky 锚点条 + "Jump to" 标签 | 标签就是这个件的可用性钥匙——没有它会被误读成 tab |
| scrollspy active 橙线（2px `::before` + 250ms） | 便宜、信息量大、"读到哪了"常驻反馈 |
| 右端情境 CTA 槽 | 常驻转化位，行业页挂 Contact 的用法直接平移成 CFE 挂 RFQ |
| hash 深链（title slug + shallow push） | 不可见管道，章节可分享/可收藏 |
| 书签哨兵数据结构 | TOC 与内容解耦，CMS/MDX 里插一个标记块就有目录项 |
| `jump_to` 埋点 | 目录使用率可量化 |
| 跳转落点补偿 = 条高 | 不做这个跳完标题会被条压住 |
| 顶部 30% 可见带 scrollspy | 见 C4——它比逐 section 算 offset 的方案稳 |

**砍掉/替换：**

| Fugro 原版 | CFE 降级版 | 理由 |
|---|---|---|
| header absolute 滚走 | **sticky 白底 header（约 64px）常驻**：logo + 收纳后的主导航 + RFQ 钮；滚过 hero 后加底边发丝线（或一直白底） | B2B 刻板印象核心件；Fugro 的 112px 透明 header 是品牌件，CFE 学不起也不用学 |
| 1.2s framer 数值滚动 | 原生 `scroll-behavior:smooth` + `scroll-margin-top: <header+条高>px` | 系统级手感，零 JS，快 2–3 倍 |
| `<button>` 假锚点 | `<a href="#slug">` | a11y + 中键/右键可用（TEARDOWN §9 同判） |
| 双层哨兵 div + 注册表 Context | 顺手在内容里给 section 标 `id` + 一个 `[{id,label}]` 数组渲染条 | 少一层间接；Fugro 那套是为 Storyblok 编辑自由插块服务的 |
| 章名编辑化命名 | 功能化命名（Products/Capabilities/Case studies/Contact） | 刻板印象友好 |
| （无） | **顶部 2px 细进度条**：`scaleX = scrollY/(docHeight-vh)`，挂在锚点条底边 | Fugro 没有的净新增；便宜（一个 rAF 监听），补"这页还有多长"的缺 |

### C3. 两形态对比（同一页的两种顶栏形态）

### C4. 一个实施细节提醒

Fugro 的"顶部 30% 可见带"（rootMargin `0 0 -70% 0`）比常见的"section 顶边过中线即 active"更不易抖动：section 只要在顶部带内就算 active，快速滚动时高亮跳变少。CFE 实施时保留这个值，但把 Fugro 的"上滚回退前一个"分支简化掉——用 `entries` 里最后一个 `isIntersecting` 的目标即可，行为差异只出现在极端快速上滚。

## E. 图文关系（"图和文要共舞"在 Fugro 的四种做法）

**总原则：图不带框。** 全站图件 radius 0、无 padding、无图内说明栏；图要么做底（文字压上来），要么做列（与文字并置），要么裸放进卡（贴卡边出血）。卡阵里的卡有 1px 发丝边框（`cssom-sheet-1.css:569-584`），但那是卡框不是图框，图在卡内仍满边出血。

### E1. 满幅图层 + 文字压图（hero 家族）

- 图片层 = 绝对定位 + 视差：`width:105%; height:calc(100% + 260px); margin-top:-130px`（`cssom-sheet-1.css:843`），DOM 实时捕获 `transform: translateY(-97.18px) translateZ(0)`（`home-1440-cookies-gone-dom.html` hero）——图层比视口大 5%，滚动时 translateY 产生慢移。
- 双层 scrim：顶部 224px 黑→透明（保护 header），底部 50% 透明→黑 .7（保护文字）（`cssom-sheet-1.css:616-618`）。
- 文字布局：左列 H1（58.33% 宽），右列使命句 + 视频钮，`align-items:flex-end` 全部沉底；右列文字上方加 1px 半透明发丝线（`::before`，opacity .5，`cssom-sheet-1.css:855`）。

### E2. 单张大图 + 横滑文字轨（imageReelCarousel，首页行业件）

- 一张响应式比例大图：375/752(0)→3/4(≥640)→4/3(≥1024)→**16/10(≥1250)**（`cssom-sheet-1.css:771-780`），三张图叠放、只显示当前项（`.cSTVkZ{display:none}`），点轨上文字项换图。
- 底部 scrim：`linear-gradient(transparent 59.44% → rgba(0,0,0,.75) 93.87%)`（`cssom-sheet-1.css:789`）。
- **文字轨直接压在图上**：左下 label（Aktiv 500 24–26px，白）+ 横滑轨道（每项 = 标题 21–24px + 描述 16px + 白箭头，轨宽 80%→45%→33.33%-16px）；轨道 scrollbar 定制 2px 白条（`cssom-sheet-1.css:810-813`）——轨道本身就是视觉件。
- 内容 padding（左下角）：0 40px 48px @≥1250（`cssom-sheet-1.css:790-799`）。

### E3. 分栏编辑式（heroFramedPicture 案例页 / crossLink 横幅）

- 案例页 hero：CMS 底色（浅蓝 #9CD4E5）满铺，**左文字列被上下发丝线"框"住**（`border-top/bottom: 0.1rem solid rgba(1,30,65,.16); padding:2.4rem 0`，`cssom-casestudy.css:763`）+ 右列 1:1 图（`aspect-ratio:1/1; object-fit:cover`，`cssom-casestudy.css:765-772`），图列 `padding-left:3.2rem`。整块定高 692/916px。
- crossLink 横幅（首页 Careers）：左图右文 2 列，图列内又是视差层（105% × +60px，offset 30），文字列 = label + Review 28–36px 标 + CTA 行（`border-top:1px rgba(1,30,65,.16)` 分隔，箭头 hover `translateX(8px)`，`cssom-sheet-1.css:619-689`）；整横幅 min-height 560→664px。
- 这是"图和文共舞"最抄得动的一招：**文字列用发丝线做编辑框，图片列贴边出血，两者以分栏而非层叠共处。**

### E4. 卡内裸图（featuredCardGrid / masonry）

- 案例卡：`<a>` 整卡可点 → 图块 `aspect-ratio:4/3; margin-bottom:0.8rem`（2 列时变 1:1，`cssom-sheet-1.css:537-544`）→ ■ 小方标 + "Case study" 眉 + H2（3 行钳制 `-webkit-line-clamp:3`）+ 日期。图 `position:absolute; inset 等比; object-fit:cover`（`cssom-sheet-1.css:538`）。
- 卡 hover = `translateY(-5px)` + 底线变 navy（`cssom-sheet-1.css:535-536`）；masonry 卡另有 `scale(1.03)` + 边框加深变体（`:569-584`）。
- imageWithCaption：窄图件走居中收窄（columns SM:10/MD:8 + offset 1/2，`app.js` @≈740689 搜 `imageWithCaption`），caption 是图下一行小字，无框。

## F. Footer 注意力分配

### 结构（`home-1440-cookies-gone-dom.html` footer + `cssom-sheet-1.css:858-920`）

```
footer（白底！padding 32→56px 顶 / 32px 底；margin-top:auto 钉底）
├─ Row 1（border-bottom 1px #c5ccd5）
│  ├─ 左 25%：logo 列（≥1024 border-right 发丝线；logo 高 62px；列底 padding 56-64px）
│  └─ 右 75%：
│     ├─ 33%：六项主导航（Industries/Expertise/Careers/Investors/News/About us）
│     │        Review 400 26→28→30px，垂直列表，hover #818ea0，列右侧发丝线
│     └─ 67%：
│        ├─ 订阅件："Subscribe to news alerts"（Aktiv 500 18px）+ "Sign up now →"
│        └─ 两列：Social media（LinkedIn/Facebook/X/Instagram）
│                 Contact（General contact/Our locations/Talent Community/Speak Up）
│                 列头 16px w600，链接 Aktiv 400 16px #485d76，hover navy，
│                 右列 border-left 发丝线 + padding-left 32px
└─ Row 2：法务链接（Cookies/Privacy/Disclaimer/Purchase terms，左）+ "© 2026 Fugro…"（右）
   （底部另有 BrightEdge SEO 自动注入的 "Also of interest" 相关链块——第三方件，非设计）
```

### 注意力分配判读

1. **视觉中心 = 六项巨字导航列**（26–30px Review）——footer 里最大的文字不是 CTA 不是 logo，是**重复 header 的导航**。注意：这是"结构记忆"件不是转化件。
2. 转化入口极轻：无按钮、无内嵌表单——订阅只是个箭头链接（跳独立订阅页），联系只有小字链接列。Fugro 把询盘转化放在**页身**（每页尾专家名片 + 锚点条右槽 Contact），footer 只做法人/合规/暗链。
3. 层级三档：巨字导航（30px）> 订阅标题/列头（16–18px）> 链接（16px 灰蓝）。白底 + 发丝线分隔，与页身同语言（无重底色块 footer）。
4. `footer { margin-top: auto }`（`cssom-sheet-1.css:839`）短页钉底。
5. CFE 启示：footer 大字导航列可抄（比小字堆 6 列更有编辑感）；但 CFE 的 footer 需要一个 Fugro 没有的件——**常驻 RFQ 入口**（CFE 转化面比 Fugro 窄，footer 是最后兜底位）。
